01

发现能力边界，归因物理约束，适应不同身体

Embodied capability discovery + adaptive planning benchmark。给 agent 一个陌生的身体与世界、公开可用的动作接口和自然语言目标，评测它能否发现未知能力边界，利用环境资源，并据此调整长程策略。

Unknown capability → budgeted interaction → calibrated self/world belief → resource composition → feasible strategy → execution / recovery

Capability discovery

通过有信息量的互动估计 reach、载荷、抓取、移动与接触限制。动作语法公开，物理边界按 Explicit / Partial / Latent 控制披露；不靠隐藏接口规则制造失败。

Resourceful planning

直接动作不足时，组合箱子、支撑、工具、推车、门或伙伴。环境资源改变可行解集合；每条路线需满足真实的几何、受力和控制条件。

Strategy adaptation

固定世界与目标，改变身体或已验证的控制能力。检验 agent 是否识别旧计划的不可行环节、重新构造策略，并在无需改变时保持正确策略。

核心研究问题：agent 能否发现陌生世界中与自身身体有关的物理约束，形成准确且有不确定性表达的能力模型，并把可用资源组合成长程可行策略？

定位边界：EmbodiedSWE 已覆盖 coding agent 机器人求解、解法迁移、轨迹生成及 agent 改进。本提案以“能力发现与自适应规划”为主标题；Terminal-Bench 仅保留为历史类比。拟议贡献是受控的信息披露、能力干预与诊断评测的组合，不以更多任务、Genesis 或 G1 本身作为新意。EmbodiedSWE 官方仓库。

继承 Benchmark v2 的四轴、五指标及配对实验；保留 v1 的复合任务。V3 方法提案 [external workspace]为独立路线。显式 capability memory 是待检验假设，不是参赛条件。以下任务、阈值与接口均待实现和物理验证。

02

联合建模自身能力与世界物理属性

Instance I = (T, E, C, O, W) hₜ = (o₁:ₜ, a₁:ₜ₋₁, r₁:ₜ₋₁) bₜ(C, W) = P(C, W | hₜ, disclosure(O)) Ĉₜ, Ŵₜ = bₜ 的估计摘要；π(aₜ | T, hₜ, Ĉₜ, Ŵₜ) F(a; s) = f(C_robot, P_object, G_geometry, D_dynamics; s)

T 是目标，E 是身体/团队与控制器，C 是依赖上下文的潜在能力 profile，O 是信息披露策略，W 是世界物理参数。E 约束 C。Agent 接收正常观察 o，以及 O 允许披露的能力信息，不直接读取完整的私有 C、W。

bₜ 是信念分布，Ĉₜ、Ŵₜ 是估计或摘要。反馈 r 指可观察的物理执行证据，不代表隐藏 reward、feasibility label 或 verifier 输出。动作可行性由自身、物体属性、几何和动力学共同决定；标量 reach / payload 阈值仅在明确的校准条件下有意义。

  1. 观察并提出假设。结合身体外观、本体感知、先验与已披露规格。
  2. 尝试或探测。当不确定性影响决策时，选择预算内的信息性互动。
  3. 更新自身与世界模型。对模糊反馈保留多个竞争解释。
  4. 识别缺口并构造替代解法。重新定位、延长 reach、创造支撑、搭桥、重新分配载荷或招募伙伴。
  5. 执行并修订。依据可观察结果，在 episode 内更新计划。

Effective capability 指在公开有效性约束和预算下，利用允许资源与伙伴可以实现的目标集合。物理可行性与当前策略的执行成功概率分开评测；一次控制器执行失败不等于动作物理上不可行。

03

同一个货架，四种身体，不同解法

P(strategy | goal, scene, embodiment, interaction history) 仅改变身体：(T, W, E₁) ↔ (T, W, E₂)，固定 O

目标：取回 1.3 m 货架上的红盒子。目标、平台、杆子、接收表面及有能力的伙伴在所有变体中均保持一致，仅改变主机器人身体/控制器。下面数值为 evaluator 侧示例，在 Latent 模式下不向 agent 披露。

A / REACH 1.4 m

直接取物

推断或探测 → 抓取

已验证的直接路径可行。直接执行本身也能提供证据，无须额外安排一次失败探测。

B / REACH 1.0 m + STEPPING

建立稳定支撑

识别 reach 缺口 → 移平台 → 踏上 → 抓取

验证平台高度、稳定性、承重及 stepping 控制。伸手失败可以提供缺口证据，但不是必经步骤。

C / REACH 1.0 m + POLE CONTROL

改变交互几何

判断 stepping 限制 → 用杆 → 取物

无法使用平台路线。杆子路线需要经验证的接收面、把手或转移几何，真正把盒子带到可达区域；沿着仍不可达的货架拉近或任其跌落，不能默认构成解法。

D / REACH 1.0 m + WEAK ARM

招募有能力的伙伴

推断自身不足 → 分配伙伴 → 接收目标

独立验证伙伴的 reach、载荷、交接与协调。A–D 的伙伴访问权限相同，伙伴工作和通信都计入成本。

这些是候选路线，不是四条唯一标准答案。 同一个伙伴或工具可能让多个身体共享可行策略。仅当所选路线变得不可行或可行策略集合不相交时，计入必须切换；在明确成本目标下另报效率优选切换。同一策略仍然合适时，正确不变也应得分。

四身体示意与干净的干预实验分开

A–D 为解释目的组合了多项身体差异。诊断 pilot 每次仅改变一个已验证能力轴：reach 几何、力/力矩边界、夹爪开口或移动/控制能力。固定目标、世界参数、资源、伙伴、预算、O 及兼容接口；重新验证碰撞、视角与控制器能力。只改 metadata 不构成物理干预。

不变、无解与不确定对照

加入无关或外观身体变化、共享可行策略，以及不存在允许解法的任务。对有证据的不确定性与弃权给予相应评价；策略改变只有与已验证的可行性或成本差异一致时才有价值。

G1、高柜彩盒与可移动箱子：把解法发现和执行分开

在上述支撑路线中，agent 先识别可能移动且可承重的箱子，再尝试搬运、放置、踏上和取物。候选程序为 inspect → move(crate, cabinet) → place → step_onto → reach → grasp(target)；这些是本 benchmark 拟议的技能语义，不是现有控制器已提供的完整 API。

箱子滑动或踏上失败后，agent 根据可见接触、姿态与位移证据重新估计稳定性、调整放置或选择另一条允许路线。轮式双臂可能需要工具或伙伴；无抓取能力的身体可能需要转移机制，或在证据充分时报告无解。身体名称本身不证明某条路线可行，所有步骤和转接都需要验证。

04

四个任务主类 + 一个 Composite Challenge Split

Task × Constraint × Embodiment × Capability Knowledge Access / Manipulation / Environmental Augmentation / Collaboration / Composite

Task 定义需求或增强机制，Constraint 标注物理限制，Embodiment 指定身体/团队，Capability Knowledge 控制信息披露。四者是独立的设计维度，不意味着统计独立或任意组合都成立。四个主类用于报告；Composite 是任务轴的第五个取值，单独组成 challenge split。

01 / ACCESS

Mobility & Access · 访问能力

目标已知，但机器人的移动能力与环境不匹配。例如机器人宽于门口、门被物体挡住、开门需要 pull 而只支持 push、台阶、gap，以及更长但可行的绕行路线。

评测链：mobility constraint → alternative access strategy。验证通道宽度、转弯空间、台阶/地形控制，以及障碍物是否确实可移动。

02 / MANIPULATION

Manipulation · 物体操作

抓取、搬举、保持和重新定向属于 manipulation 需求；reach、payload、gripper、dexterity 与几何属于贯穿任务的约束。例如 1.4 m 高目标对比 1.0 m 可达范围、8 kg 物体对比经验证的 3 kg 搬举限制，以及物体宽于夹爪开口。

评测目标：尝试前预测哪个直接动作不可行。数值是受控示例，物体质量仍属私有状态。单臂“撑住盖子并取物”只有在经验证条件排除了顺序操作与支撑替代时，才能判为不可行。

03 / ENVIRONMENT

Environmental Augmentation · 环境增强

环境资源改变 effective capability。Tool use 是其中的 subclass；有用资源也可以是普通箱子、木板、桌子或推车。

  • Extend：杆子延长交互 reach。
  • Support：稳定平台改变有效高度。
  • Bridge：木板扩大可访问空间。
  • Mechanical advantage / 载荷重新分配：杠杆、滑轮或推车改变作用力与运输需求。

移动桌子也可形成中间可达表面。每种收益都取决于已验证的接触与控制条件。

04 / COLLABORATION

Collaborative Capability Augmentation · 协作增强

机器人认识到伙伴可以补足自身限制。例如移动机器人把物体送进强固定臂的 workspace、协同搬举，以及能进入窄区的机器人将物体交给 reach 更高的机器人。

弱机械臂不能被默认能够搬运 8 kg 物体，应验证 cart/push/drag 等运输机制。同样，m > P_A, m > P_B, m < P_A + P_B 只是联合搬举的初筛条件；载荷分配、抓取几何、协调与执行器限制仍须验证。

标注规则：Access 和 Manipulation 描述任务需求，Environment 和 Collaboration 描述弥补机制，彼此可能重叠。预先指定 primary category，并附加 deficit/mechanism 标签；报告交叉覆盖，每个 family 在配额中仅计一次。这些可能提示解法的标签不向 agent 公开。

Composite Challenge Split · 组合多种能力缺口

目标：把阁楼上的红盒子带到厨房。

拟议场景包含被堵住的楼梯、储藏室里的木板、挡住储藏室的重柜子，以及附近的另一个机器人。一条候选依赖链是：

  1. 诊断访问问题。识别当前路线为什么不可用。
  2. 发现可能用作 ramp 的资源。木板可能形成替代路径，但暂时拿不到。
  3. 招募具备相应能力的伙伴。在力与抓取限制经验证的前提下，协调清理柜子。
  4. 取出并放置木板。检查长度、坡度、固定、承重及 embodiment 的通行能力。
  5. 取回并运送目标。通过这条或其他允许路线满足最终状态。

这是候选场景，不是已运行的物理解法。木板必须真正形成有效路径；humanoid 标签不自动意味着能走 ramp 或楼梯。复合任务结合多类需求与嵌套前置条件，而非简单串联独立 puzzles。

前版“能力认知 → 环境 → 协作”保留为评测视角，不再作为另一套任务 taxonomy。通用 API 与隐藏 verifier 边界保持一致；团队构成、通信和伙伴工作量都需要控制并记录。

05

物理约束贯穿所有任务类型

同一种物理限制可能阻碍访问、操作、环境增强或协作。约束标签与 primary task category 分开；一个实例可以同时具有多个约束标签。

  • Kinematic · 运动学Reach 包络、关节限制与运动可行性。
  • Dynamic · 动力学执行器力/力矩、载荷、加速度与搬举限制。
  • Geometric · 几何空间间隙、物体匹配、碰撞与抓取几何。
  • Contact / friction · 接触与摩擦牵引、滑动阻力、接触姿态与卡住。
  • Stability · 稳定性支撑、倾覆、平衡与载荷分配。
  • Morphological · 身体形态宽度/高度、手臂数量、DoF 与移动结构。
  • Multi-agent dependency · 多体依赖能力互补、同步动作与角色前置条件。

为什么箱子推不动？

机器人作用力不足、物体质量大、摩擦高、几何卡住、接触姿态不佳，都是竞争解释。一次失败推箱通常无法识别唯一原因。Agent 应更新自身与世界信念，表达不确定性，并在有价值时选择能区分假设的互动。

归因诊断：分别构造仅改变作用力、质量、摩擦、间隙或接触的匹配干预，固定其余相关变量，验证因果变化，再用 evaluator 私有标签评估 agent 预测。加入多原因与观察上无法区分的情形；自身和环境的相互作用也可以是正确解释。

约束/机制标签、干预及因果标签属于 evaluator metadata。Agent 只得到正常物理反馈，不能通过 API 直接读取隐藏原因。解释得分须有预测、探测和结果支撑。

06

Embodiment 单独成轴

Fixed Arm

固定 workspace 内的 manipulation，不假设底座移动。Access 类须有合理的工作区内访问、工具介入或伙伴协助解释。

Mobile Manipulator

底座导航加操作，地形、间隙、reach 与 payload 限制均需验证。可移动不自动意味着可以攀爬。

Humanoid

Whole-body、stepping、bimanual 或 climbing，仅在具体身体与控制器支持时成立。身高与 reach 仍是需要测量的变量。

Heterogeneous Multi-Robot

由明确的各机器人 embodiment 与互补能力构成的团队配置，不是另一种单机器人形态。

07

三档能力知识：已知、部分、潜在

A / EXPLICIT · KNOWN

利用明确披露的边界

提供经校准的规格，例如 reach 0.9 m、payload 3 kg、最大台阶 0.2 m、夹爪开口 8 cm，并说明测量条件。检验规划能否遵守这些限制。

B / PARTIAL

根据粗粒度信息估计

只提供“mobile manipulator”“small gripper”“low-payload arm”等描述，不给精确阈值。结合观察、先验与交互证据形成估计。

C / LATENT · DISCOVERY

发现实际可用的能力 profile

提供身体、可用的动作接口和正常传感反馈，不给能力阈值。通过预算内交互，发现当前情境中哪些运动及通用 primitive 确实可执行。

上述数值仅为披露示例，不代表机器人通用属性。Explicit 也不公开世界私有参数或正确策略。Latent 不等于零先验：身体外观和历史都是合理证据。检查 URDF/config、机器人 ID 与 debug 响应是否泄漏阈值。

每档可见性分别交叉 Track A（通用 skills）或 Track B（连续执行，包括冻结 VLA）。公开命令语法及可观察执行状态，避免返回 oracle 前置条件判断。命令存在不代表在每种身体上都物理可行；受控配对的接口须兼容。

比较三档披露时，在隔离运行中复用同一已验证物理实例，匹配交互预算。记录探测前后的能力概率、不确定性、假设与策略。探索计入任务预算，不能免费重置仿真或查询带标签的可行性。

初始 pilot 冻结权重，允许 episode 内信念和记忆更新；持久训练或 harness 适应仅使用 development split，并在测试前冻结。配对测试 episode 之间不共享记忆，除非另设明确允许的 adaptation setting。

08

私有世界状态留在 agent 进程之外

仅供 generator / evaluator / oracle

精确物体质量、摩擦、全局位置、仿真器内部状态、可行性标签、隐藏解法图及 verifier 源码。完整 TaskSpec 属于这一特权侧。

Agent observation 白名单

RGB 或 RGB-D、本体感觉与关节状态、符合当前设定的机器人 specification、可观察的技能结果，以及可选的校准力传感。感知估计应包含不确定性和来源。

“技能失败”应描述可观察执行证据，不能返回“精确质量超过未公开 payload 阈值”之类的隐藏解释。通过感知估计世界坐标，与直接读取仿真器 ground truth 是不同的信息来源。

从显式白名单构造 AgentView，不将 TaskSpec 整体序列化后仅在界面上隐藏字段。隔离 evaluator 的进程/权限，过滤日志与错误消息，检查文件名、机器人身份、reward 通道及 API 返回中的泄漏。

隐藏 verifier 在终止后评测最终状态；测试时不提供实时 feasibility oracle 或隐藏进度反馈。公开有效性规则保持可见；精确物理边界按所选披露策略处理。真机可获得的观察通道有助于后续迁移研究，但本身不证明 sim2real 成功。

复用开放环境，重建发现评测的信息边界

开放开发 / SWE 对照

复现上游允许的源码检查、仿真调试和工具条件，按每次实验规则执行。开放模式单列结果，用于评估 program synthesis 与基础设施复现，不能和受限发现模式混合排名。

受限 discovery 评测

Agent 只访问公开 SDK、动作语法和允许的传感器反馈。可编写 solve(agent_view)，但接口对象是隔离的 RPC 客户端，不能持有原始 env、控制器实例或仿真句柄。

底层保留 EmbodiedSWE 的环境与 evaluator 接口，但 agent 容器不挂载隐藏配置、verifier、完整 URDF/资产 metadata 或可泄漏测试参数的源码。测试时禁止读写原始状态、reset/restore、修改物理参数和替换冻结执行器；限制由进程、文件权限和 RPC allowlist 实施，不能只写在 prompt 中。公开通用 SDK 与开发示例，并对日志、异常、路径、进程访问和序列化结果做泄漏检查。

上游 solve(env) 协议允许读 benchmark 源码，fresh grading 禁止 reset 和直接写仿真状态；具体开发工具取决于该次运行的 rules。我们在此基础上收紧测试时的信息与权限边界，而不是宣称上游没有隐藏评分。官方评测协议。

公开模型先验无法完全消除。对测试配置实施不暴露真值的物理/控制干预，报告身份先验与历史记忆的影响；主评测隔离 episode 记忆。开放开发限于 development splits，不能先读取当前隐藏测试实例，再把同一 agent 的结果称为 Latent discovery。

09

TaskSpec 才是任务定义的 source of truth

World ≠ Goal / Task ≠ Embodiment

将 WorldSpec（布局、对象、资源及潜在物理参数）、GoalSpec（目标与公开约束）和 EmbodimentSpec（身体与控制配置）分别版本化，再由 TaskSpec 绑定。沿用第 02 节符号：T 表示目标/任务语义，W 表示世界，E 表示身体与控制器；四轴仍是报告维度，不要求遍历所有组合。

TaskSpec = bind(WorldSpec, GoalSpec, EmbodimentSpec, Disclosure, Budget) Same world + goal, different body → capability / strategy intervention Same world + body, different goal → goal composition test

例如同一房间分别要求取高处盒子、把盒子送至门外或清空通道；每个目标独立验证允许的终态。比较身体时固定目标、初始世界、资源、伙伴访问权限与预算。EmbodiedSWE 的 scene 当前携带 goal，但 robot 已单独组合；本设计扩展的是多目标任务语义与受控评测，不将其现有组织方式说成不可突破的架构限制。设计说明。

保留 simulator-independent 任务中间表示。首先绑定到 EmbodiedSWE / Isaac Lab；后续 Genesis 或真机适配器消费同一受支持语义，避免依赖某个仿真器导出的 scene 作为唯一任务定义。

共享核心：TaskSpec、RobotSpec、ObjectSpec、CapabilitySpec、ObservationSpec、Skill API 及 success predicates。版本化结果协议和 worker 协议连接执行与评测。Core 模块不 import 仿真器；compiler 映射资产、物理、传感器和控制器语义，不另写一套任务目标。

共享资产定义，验证实际物理实现

Robot canonical asset：URDF

URDF → Genesis import URDF → Isaac importer → USD

锁定 meshes、关节约定、惯性、限制及控制器配置。执行器行为与传感器设置仍需在各 backend 中明确配置。

复杂物体与环境：优先 USD

Genesis 文档支持 USD 加载，Isaac 技术栈使用 USD 资产。共享文件不保证接触行为、关节、材质解释或视觉输出完全相同。Genesis USD · Isaac Lab assets。

TaskSpec 以明确的单位和约定描述 mass、friction、restitution、joint limits 与 dimensions；backend adapter 映射到引擎设置并记录覆盖项。通过校准测试检查碰撞几何、惯性、缩放、solver/timestep、力/力矩限制及抓取行为。

能力字段描述测得的工作范围。Reach 随配置变化；payload 取决于姿态、加速度、抓取与执行器。能力变化要由模型/控制器变化产生，再通过任务相关测试确认；不能将一个标量字段当作引擎已强制实现的物理限制。

后续跨引擎验证时，将同一 canonical robot 编译到两个引擎，派生资产按源 hash、importer 版本与选项缓存。Genesis 支持 URDF，Isaac Sim 提供 URDF → USD 导入；导入后的物理仍须验证。Genesis 资产 · Isaac URDF 导入。

任务生成：从交互数据到可验证的问题实例

借鉴 GRAIL 的资产与地形生成流程，为任务模板采样几何、布局、物体及身体配置。这里的提案扩展是生成需要发现解法的问题，并建立可行性证据与配对干预。

Task template → sample scene / objects / terrain / body → bind TaskSpec in primary engine → validate physics and candidate routes → assign paired splits → release episode with private evidence

可解实例保留 evaluator 私有的构造性解法；无解对照需要有依据的界限，不能把控制器失败当作证明。生成的视频或轨迹只能用于开发、控制器训练或私有验证，不能成为测试时的专家提示。记录生成器版本、资产来源、种子和筛选失败；按关联资产与解法结构审计 split 泄漏。首个 pilot 可使用程序化几何，不依赖完整视频生成流程。

先验证研究问题

LATER / GENESIS

独立稳健性验证

Pilot 成立后，为共同支持的刚体任务接入 Genesis adapter。按 family、约束与身体分层选取子集，报告覆盖率和差异；不预设吞吐收益，也不因兼容问题静默删掉字段。

五类 canonical checks，按执行器覆盖推进

  1. Reach：直接抓取与有效替代路线。
  2. Payload：搬举与推车/伙伴运输。
  3. Gap + bridge：放置、支撑、承重与通过。
  4. Box + height：稳定箱体与兼容 stepping。

隔离 agent，复用受信任的执行层

Agent container: public SDK + solve(agent_view) ↓ allowlisted RPC / budget accounting Trusted worker: EmbodiedSWE adapter → Isaac Lab environment ↓ evaluator-only state / result Private verifier + capability / attribution diagnostics Later: separate Genesis worker for matched validation

Agent、技能执行器与仿真器的分层接口

Contact plan 是可选的中间表示。例如 hands ↔ crate; feet ↔ floor，随后 feet ↔ crate，再到 hand ↔ target。这只表达预期接触；适配器仍需生成可执行目标或参考，处理时序、支撑、转换与终止。它不能把符号关系自动变成稳定运动，也不是 SceneBot 原生输入格式的完整复现。

任务解法必须由 agent 产生。Track A 适配器可将已选的通用技能展开为局部参考，但不得根据隐藏解法图替 agent 挑箱子、安排步骤或补齐长程计划。记录 agent 程序、适配器展开与实际接触三层轨迹。失败只返回可观察状态；恢复尝试和适配器内部重试计入预算。

接入门槛：逐项声明支持的身体、输入模式、观察依赖、技能范围、转接及终止条件。先验证候选技能和连续转接，再运行整条取物任务；分别报告控制器复现、跨引擎适配和 agent 求解结果。ULTRA 现有 IsaacGym / MuJoCo 路线仍需适配本项目主引擎，不能将 IsaacGym 当作 Isaac Sim。参赛 agent 在同一对照内共享冻结的执行器。

Physics Agreement

在容差内比较预定义物理量与检查，例如力响应、滑动、支撑、倾覆或桥稳定性。报告差异和原始证据，不要求轨迹相同。

Feasibility Agreement

比较已验证的直接/增强动作及路线 predicates。学习策略失败不足以证明物理不可行；使用构造性控制器、针对性测试和有依据的界限。

Strategy Agreement

比较哪些候选策略仍然可行，以及在已定义成本时的排序。不同成功路径可以语义一致。Agent 实际策略稳定性与已验证解集分开评价。

C_sim2sim = 已确定且匹配的可行性 predicates / 全部预定义 predicates 同时报告：未决覆盖率、不一致率和各 family 结果

接触存在随机性时重复试验，预设判定 margin，保留 uncertain 类别。两个 uncertain 不能计为匹配。Physics 与 Strategy Agreement 各自定义测量依据，不把三项分数混成不明含义的平均值。

分层发布门槛：主集合要求在固定 Isaac Lab 配置中验证核心可行性、干预标签、观察隔离和执行器覆盖。另设 cross-engine validated 子集，必须同时具备 Genesis 与 Isaac 的判据证据；未测第二引擎的任务不得声称跨引擎稳健。

跨引擎不一致的任务暂不进入 cross-engine validated 子集；若主引擎核心标签本身未决，也不能进入主集合。校准和重跑后再决定纳入，保留候选数及各 family 剔除率。差异可能来自导入、控制器、数值设置或脆弱的任务定义。按物理证据校准，不能为了偏好的 agent 结果调参。

区分候选总体、主引擎正式集合与跨引擎验证子集，并报告抽样与筛选偏差。一致性支持两个已配置引擎中的受测判据；两边仍可能共享建模误差，因此不能据此保证真机迁移或普遍 simulator independence。

14

五个主指标：从发现到执行

  1. Task Success · 任务成功

    在公开有效性规则和固定总预算下，用隐藏最终状态判断成功；探测与伙伴工作都计入预算。报告样本数及不确定性区间。

  2. Capability Calibration · 能力校准

    执行前预测 P(feasible | action, context, evidence)，对照已验证的私有 physics labels，计算 Brier score、reliability curves 及固定分箱的 ECE。AUROC 衡量区分能力，不是校准指标。报告 false-feasible、弃权与未决标签覆盖率；另行评测当前执行器成功概率。

  3. Capability Discovery Efficiency · 能力发现效率

    达到预设估计误差或已验证策略判据前，需要多少交互、物理时间与成本。例如固定 reach 校准条件下，r = 0.95 m、r̂ = 0.97 m，误差 |r̂ − r| = 0.02 m。报告估计区间和预算耗尽仍未达标的运行，不能只统计成功发现者。非标量能力使用 held-out probe 预测误差。

  4. Strategy Adaptation Score · 策略适应

    根据实际轨迹验证跨身体策略的可行性，分别评价必须切换、明确成本下的效率优选，以及正确不变。不同可行集合仍可能重叠；单纯换策略不得分，也不设置唯一口头标准计划。

  5. Constraint Attribution · 约束归因

    失败后预测 reach、payload、friction、gripper geometry、mobility、collision、stability 或组合原因。使用已验证的单因素干预，并单列多原因/模糊情形。可识别标签报告各原因 precision/recall 与概率质量；证据无法区分原因时，合理的不确定性应获得认可。

Oracle 质量：标签需要构造性解法、针对性物理测试或有依据的不可行界限。接触敏感任务重复测试，记录随机与未决结果。学习策略失败不构成不可行 oracle。预测评分在 evaluator 内完成，不在线向 agent 返回标签。

补充诊断：资源/伙伴消融下的 augmentation gain、恢复成功率与成本、held-out embodiment 泛化及世界参数泛化。仅身体、仅世界和二者联合变化分开报告；报告 category × constraint × body/team × knowledge 覆盖，并单列 Composite 结果。

匹配基线与消融

比较不使用 embodiment 信息的 agent、规格条件规划、容量匹配的记忆反思、能力感知规划与能力引导探测。消融自身模型更新、世界模型更新、归因、探测及资源/伙伴访问。各基线匹配可见性允许的信息和预算；oracle capability 单列为诊断上界。

测试前冻结系统并隔离 episode 记忆。使用重复配对种子、分 family 汇总、样本数及不确定性区间，记录 tokens、调用、动作、物理时间、重置、伙伴工作与人工干预。若声称 optimal strategy，须定义成本及最优性证据，否则使用 best-known feasible routes。

固定执行器的求解对照：增加 evaluator 提供已知可行程序的诊断运行，估计执行器瓶颈；该程序不提供给正常参赛 agent。对自然失败和预先声明的扰动，分别报告恢复率、额外动作及成本，并区分计划错误、接触/技能转换失败和低级控制失败。接触程序仅用于轨迹诊断，不要求匹配唯一标准接触图。

对照 EmbodiedSWE：迁移帮助与能力发现分开测

主 discovery 组不提供源任务成功程序，比较同一 coding agent 的无能力更新、普通反思、能力模型及主动探测版本。另设 source-solution hint 诊断：分别给出在目标身体仍可行、已不可行或只改变效率的源策略，评估接受、拒绝或重构是否正确。源解法通过同一公开输入提供给所有匹配方法，不泄漏目标能力真值。

开放 SWE 对照与受限 discovery 对照分别报告；先固定观察、执行器、动作空间和预算再比较方法，避免把信息差异当作算法收益。Track A 技能辅助与 Track B 连续动作分别评测；不能将现成技能带来的优势归因于能力发现。新增报告旧计划无效步骤识别、无效重复尝试及恢复成本，仍以五个主指标为核心。

15

围绕 embodiment 条件化决策建立比较

最直接的比较：EmbodiedSWE。它已覆盖 coding-agent 机器人长程求解、跨任务/跨身体迁移、解法扩增及生成任务用于 agent RL；本提案需在这个基础上证明额外评测价值。

官方项目报告 28 tasks / 6 suites / 17 embodiments / 5 controllers。其迁移实验向 agent 提供已验证源解法，测量目标任务求解收益；跨身体实验包含 Franka 解法向其他机械臂迁移。官方项目与迁移实验。

已覆盖的共同部分

自然语言任务、编程与仿真调试、隐藏离线评分、可插拔身体与控制器，以及迁移和数据生成。增加任务数、更换仿真器或加入 G1，均不足以单独支撑本项目的研究区别。

拟议的额外检验

未知且经干预的能力边界 → 预算内探测 → 校准与因果归因 → 资源组合 → 策略重构。以固定 world + goal 的配对实验检验这一链条，并匹配同一执行器与信息条件。

避免过强结论：开放源码不等于全部能力已知；跨身体迁移也可能包含重规划。公开材料尚未建立与这里完全相同的三档披露、能力校准与强制策略切换配对协议，这只是待逐项验证的差异，不能推断 EmbodiedSWE agent 不会发现能力。其 README 已明确希望刻画身体间差异。框架设计。

RLE-BENCH / 机器人工程

RLE-Bench：将 coding agent 作为机器人学习工程师评测

RLE-Bench 包含四类方向下的九个任务族：交互控制、策略开发、感知与估计、机械设计。任务提供工程规格、容器化工作空间、工具与资源预算；通过仿真评估解法，并提供视觉与文本反馈。官方仓库（核查于 2026-10-10）。

与本提案的关系：机器人问题求解、反馈驱动迭代、策略训练和身体设计均是相关比较点。本提案拟重点检验受控能力披露、自身/世界约束归因，以及固定世界与目标的配对回合中的策略适应。主张研究区别前，应逐项对齐任务协议、信息访问与预算；仅凭仓库概述，尚不能判定 RLE-Bench 是否检验了相同的能力发现协议。

三个互补的执行与生成基础

ULTRA / CONTROLLER

待评测的层：goal → capability / affordance discovery → planning → tool / contact use → execution → recovery。这些工作强化了控制与数据基础；本 benchmark 检验无任务专属参考时的解法发现，以及受控身体变化下的策略适应。已有长程控制演示与这一评测问题需要分别比较，不能简单声称它们“不做长程任务”。

先联测能力发现、约束归因与策略适应

最小决定性场景：先锁定同一房间、高处目标、支撑箱、工具、接收面与可访问伙伴，建立 reach 或移动能力的单因素配对。检验“目标未变，旧计划某一步变得不可行，agent 能否用证据发现并改写计划”。无抓取、固定臂或不可踏步的身体不自动有替代解；先验证工具、运输与协作条件，必要时保留无解对照。

主假设：在 Partial / Latent 下，预算内互动改善能力与世界估计，并相较匹配反思基线，提高有效重规划和任务成功；不以低成功率或看起来复杂来证明 benchmark 有效。
  1. 复现与隔离。先复现上游一个任务及 grading，再建立受限 AgentView，验证真实低级执行和信息边界。
  2. 建立配对证据。测量直接与资源增强路线；加入必须切换、效率变化、正确不变及无解情形。仅世界干预另列。
  3. 匹配三档披露。使用相同身体/控制器配置、随机化分布与预算。主组无源解法；带源解法组单列。
  4. 采集决策前后记录。记录能力概率、归因、选定资源与计划，再对照探测证据和实际轨迹，定位哪个步骤引起改写。
  5. 检验因果链。做探测、自身/世界模型和资源访问消融，报告五指标及执行器瓶颈；成立后再扩到更多目标、身体和任务族。

工程顺序与 backend 发布条件见 第 11 节及 第 13 节。Held-out 身体族、身体/世界联合变化、长程复合任务及跨引擎稳健性分开报告。

首版设计：24 个 seed families

配额为 Access 6 个 + Manipulation 6 个 + Environmental Augmentation 6 个 + Collaborative Augmentation 4 个，再加 Composite Challenge 2 个。下列清单是任务编写草案，不是已实现数据集。

Access · 6 个任务族
  1. A1 · 窄通道身体宽度与转弯空间；替代路线。
  2. A2 · 堵塞门口清理可移动障碍或绕行。
  3. A3 · 推拉门限制可用作用方向与门把手可达性。
  4. A4 · 台阶与坡道经验证的地形通过能力与路线选择。
  5. A5 · 跨 gap 访问可跨越范围与替代访问路径。
  6. A6 · 长距离可行绕行最短路线受空间限制，需选择绕行。
Manipulation · 6 个任务族
  1. P1 · 高处目标可达性固定目标下的 reach 范围干预。
  2. P2 · 搬举载荷限制经验证的搬举限制与物体需求。
  3. P3 · 夹爪开口限制夹爪范围与允许的抓取几何。
  4. P4 · 保持与操作单/双末端执行器；检查支撑替代方案。
  5. P5 · 大物体重定向物体尺寸、工作空间与动作限制。
  6. P6 · 腕部载荷与抓取姿态随姿态变化的力矩与抓取稳定性。
Environmental Augmentation · 6 个任务族
  1. E1 · 杆件延伸用适合的杆件延伸交互范围。
  2. E2 · 支撑平台兼容 embodiment 的稳定升高。
  3. E3 · 木板搭桥跨度、固定、承重与通行检查。
  4. E4 · 杠杆辅助支点、作用力与位移约束。
  5. E5 · 推车运输滚动阻力、控制与载荷支撑。
  6. E6 · 中间可达表面调整桌子以支持分段操作。
Collaborative Augmentation · 4 个任务族
  1. C1 · 移动到固定臂交接将物体运入强机械臂 workspace。
  2. C2 · 联合载荷操作验证协调载荷分配与抓取。
  3. C3 · 窄区到高处接力互补的访问与高处操作能力。
  4. C4 · 保持/操作角色分配将稳定与操作分配给适合的伙伴。
Composite Challenge · 2 个任务族
  1. X1 · 阁楼取物伙伴 → 柜子 → 木板 → 访问 → 运送。
  2. X2 · 工作台资源链获取资源、清理访问、协作、验证终态。
6 + 6 + 6 + 4 + 2 = 24 个 seed families 24 × 10–20 个变体 = 240–480 个候选实例 验证与覆盖平衡后的目标：约 250–400 个实例

一个物理实例固定目标、场景、身体/团队及潜在能力/世界参数。每个 Explicit/Partial/Latent 运行对应协议实例 (T, E, C, O, W)；披露条件单独报告，不重复计为新物理任务。一组 counterfactual pair 连接两个实例；配对关系单独统计，不重复计作新任务。如果初始候选只有 240 个，就需要额外生成有效实例，才能达到至少 250 个的目标。

先生成受控 body-only 配对；scene-only 的资源或约束变化单独作为干预族。归因于 embodiment 时，不同时改变身体与场景。纳入必须切换、仅效率变化、保持不变及不可解实例。

区分参数泛化与未见 family/未见组合泛化。默认将关联变体分在同一 split；若刻意使用 shared-family、held-out-parameter 划分，须单独命名并审计泄漏。Composite 测试图不能复制开发集的解法结构。

先证明发现与适应，再扩任务和引擎

  1. 复现上游固定 commit、环境、资产与 robot/controller，复现一个任务及 fresh grading。
  2. 建立边界与语义World/Goal/Body 绑定、三档披露、RPC 隔离、隐藏参数与泄漏检查。
  3. 决定性 pilot一个世界与目标，受控能力变化；验证探测、重规划及不变/无解对照。
  4. 扩充覆盖逐步加入五类 canonical checks、多个目标和 24 个 seed families；验证后再追求规模。
  5. 独立跨引擎验证Genesis 适配共同支持的子集，报告 Physics / Feasibility / Strategy Agreement。
  6. 后续拓展考虑 250–400 实例、5–10 个真机任务；任务生成与 agent RL 在主假设成立后另设实验。

首轮投入重点：复现、信息边界、干预标签与匹配对照。撤销旧版 40% 共享 / 40% Genesis / 20% Isaac 的固定比例；依据复现与 pilot 结果估算工作量。
