任务设计指南

先把任务设计对，
再写一行代码。

01 · 十一条硬要求

每一条都要在任务卡里有交代

  1. 多个可交互物体，不给直接指示。场景里有多个能推、搬、放、踩、连接的物体；指令只写目标和公开的合规约束。第 02 节
  2. 分层建立可解性证据。少量完整参考证明声明配置可完成；技能验证适用条件；随机实例做预算内筛查；实际执行按需生成局部轨迹。不要求每个随机实例有完整解。代表证据由人工审阅并独立复现。任务验收第 03 节
  3. 最终目标至少涉及一类能力：使用工具或先达成前置条件；复杂交互、力矩或 WBC 计算；非直观的解。第 02 节
  4. 按 Terminal-Bench 的难度设计。强 coding agent 需要 4 小时以上的迭代，求解时长不设上限。第 02 节
  5. 只用机器人原生或可加装的传感器，不能作弊。不给空间坐标、物体位姿、物性、分割图或用途。第 08 节
  6. 考虑特殊情况。绕开考点的捷径在设计时剔除；剩下的合理非常规解法按它实际达到的状态自动给分。第 07 节
  7. 严格防止绕过和 reward hacking。默认不信任；攻击清单、每个阶段的反例集、漏洞测试；评测全自动，人工只在任务验收时看录像检查任务和评分器。第 09 节
  8. 初始状态尽量随机。随机化须声明范围和筛查状态，不把生成合法几何等同于可解；检查捷径，不能让解题关键只能靠真值得知。第 04 节
  9. 只分三层难度，逐层叠加。只有必要工具 → 加入换个身体才能用的工具 → 加入干扰项。第 05 节
  10. 可拆分成子任务，保留课程学习的可能。子任务用状态定义完成条件，有能单独开始的起始状态。第 06 节
  11. 用 Genesis / Isaac Lab 搭建，尽量用官方素材和精细素材库。机器人用官方模型，物体优先用仿真器官方素材和部件级、带物性的素材库。第 03 节

12 项当前还差多少：已选完整见证、待补低层动作与轨迹映射

设计可行性的最低目标：高层计划→低层动作计划→实际轨迹的转换有具体证据，并至少有一条能够生成、连续执行成功的端到端专家轨迹。例如“登上箱子”展开为重心转移、先后抬脚与建立支撑，再对应实际轨迹段。只证明声明配置中的构造性实例，不要求任意随机状态都可解、任意技能拼接或通用滚动规划器先完成。已有完整轨迹可以在核对生成来源和映射后复用；范围扩展另列。三层转换要求

设计原则修订 · 2026-10-26

先生成分层计划，按需生成局部轨迹

不把为每个随机实例生成完整解作为前置要求。主要产物是高层计划、技能选择与约束、关键状态和可行性检查结果；完整轨迹只属于部分代表性验证实例。

层级必须交代的内容证据边界
任务级少量预先选定的完整成功案例，说明声明配置下能完成任务。样本成功不证明整个随机范围全部可解。
技能级进入／退出条件、距离、载荷、姿态、支撑与接触、适用范围及失效条件。未标定的适用范围留空；失败搜索不证明不存在解。
实例级关键可达性、碰撞、支撑、载荷、段间衔接和预算检查；必要时只做困难片段短仿真。缺证或预算耗尽记“未确定”；筛查通过不等于完整执行成功。
执行级根据当前观测生成活动阶段的短段轨迹，滚动规划和修正。实际状态满足下一阶段条件后才推进，不能用恢复理想快照代替衔接。

阶段之间传递实际位姿、速度、抓持状态、接触拓扑与力、支撑几何、已提交阶段、剩余任务时间及估计不确定性。轻微抖动可按功能条件接受，公开物理限值和评分条件继续有效。

自建场景可优先在有证据的技能适用范围内采样；基准预定随机测试保留全部抽样、拒绝、超时和失败，不只保留容易成功的实例。范围内采样本身仍不构成完整可解证明。

四类实例状态及验收门槛 · 12 项任务规划 · 机器可读政策。路线与特权证据只供作者和评审，不能放入 agent 可见材料。

02 · 场景、目标与指令

多个可交互物体，目标清楚，路线不说

对应 R1、R3、R4。

可交互物体（R1）

  • 场景里要有多个能推、搬、放、踩、连接、卡住、撬动的物体。只有一个物体、用途一目了然的场景不符合要求。
  • 物体分三种：必要工具、本机器人用不了但换个身体能用的工具、干扰项。三种怎么组合，由难度层决定（第 05 节）。
  • 物体的用途要能通过实验发现：推一推、抬一抬、站上去试试，传感器上能看到结果。

指令怎么写（R1）

指令只写目标和公开的合规约束。物体用中性名称（颜色、编号），不说用途，不给路线和步骤，也不用“堆”“爬”“撬”“卡住”这类暗示做法的词。

写法例子判断
只说目标“把红色箱子放到地上的绿色目标区。”可以
公开的合规约束“搬运过程中箱子不能放在台阶上。”可以 约束是规则，不是提示
说出用途和路线“用地上的箱子垫脚，把红色箱子取下来。”不可以
给出步骤“先把门卡住，再把箱子搬过去。”不可以
名称暗示用途“台阶箱”“楔子”“杠杆”不可以 改成“棕色箱子”“物体 A”

最终目标涉及的能力（R3）

至少涉及下面一类，可以多类：

能力含义现有任务里的例子
工具 / 前置条件要先用某个物体改变环境，或先达成某个状态，目标才可能完成。H1 垫箱子取物；H2 用推车运重物；H3 双 G1 扶门协作，或用重箱独立顶门
复杂交互 / 力矩 / WBC需要全身协调、负载下保持平衡、算力矩或协同出力。H6 抱箱上楼梯；H5 撬起重箱；M2 双机抬长箱
非直观的解最直接的做法一定失败，要换思路；或者有看似有用的陷阱。H1 高窄干扰箱；M3 把另一台机器人当工具

难度（R4）

  • 目标是让强 coding agent 需要 4 小时以上的迭代才能解出。求解时长不设上限，耗时和 token 都要记录、报告。
  • 难度来自：依赖链的深度、工具的组合、需要恢复的失败、从深度和点云里估计几何、对自身身体能力的判断。
  • 难度不应该来自：画面杂乱、重复动作、为难而难的精度要求、只有读真值才知道的信息。
  • “长程”按依赖深度、工具组合、持久状态和失败恢复来定义，不按视频时长（v5 第 10 节）。
  • 难度试跑太快解出时，加深依赖（更多前置条件、物性变化）、扩大随机范围，或者换更难分辨的干扰项。

可解与不可解的回合

任务可以包含故意不可解的回合（比如 H1 的 infeasible 类），agent 要调用 declare_infeasible 声明。“不可解”必须写明验证范围（试过哪些办法、为什么不可能），不能只因为某个 agent 失败（v5 第 11 节）。对可解的回合声明不可行，会单独标记。

多机器人任务

先测单台机器人能不能完成，分清“必须协作”和“协作只是省事”。场景里有两台机器人不等于协作任务；单机能做的，就改标签，或者调整长度、质量、拖拽力让单机做不到（v5 第 9 节）。

03 · 仿真器与素材

Genesis / Isaac Lab，官方模型，优先用官方素材和精细素材库

对应 R11。

仿真后端

  • Genesis 优先。沙箱的可信 worker 跑在 Genesis 上（当前 1.4.3）。新任务至少要有 Genesis 后端。
  • 推荐同时对齐 Isaac Lab（本机环境为 Isaac Sim 5.1 + Isaac Lab 2.3.2）。两个后端共用同一个任务核心（TaskCore）：同一个种子、同一个回合序号，抽出的场景完全一样。H1、H2 及历史单 G1 H3 有两个后端；当前双 G1 H3 和 H6 仅验证 Genesis。
  • 对齐要有一致性检查。同一组指令在两个后端上跑，比较物体轨迹、接触和判据结果；差异和原因写进任务 README。
  • 仿真设置固定写进任务卡。时间步、子步、求解器、接触参数、自碰撞开关；评测时不能改。
  • 写明后端的限制。比如 Genesis 1.4.3 没有射线传感器，H1 的 MID-360 LiDAR 是用四个深度相机拼出来的，扫描图案是规则网格。

机器人模型：用官方模型

  • G1：MuJoCo Menagerie 的 unitree_g1（BSD-3-Clause），由 setup_assets.py 按固定提交下载；传感器安装位姿取自 Unitree 官方 URDF。
  • Go1 / Go2：用 Unitree 官方或 MuJoCo Menagerie 的模型；Isaac Lab 自带 Unitree 机器人的配置。
  • 不要私下改模型的质量、力矩上限或关节限位。需要变化的身体参数（力量、负载）在任务里显式随机化，并公开范围。

物体素材：按优先级选

优先级来源适合做什么现有任务里的例子
1仿真器官方素材：Isaac Sim 官方素材库、Genesis 自带素材推车、货架、工业物件；通常自带碰撞体和物理属性H2 的推车（NVIDIA Dolly）
2精细素材库：部件级、带关节或实测物性的库，例如 PartNet-Mobility（SAPIEN，带关节的柜子、门、抽屉）、Google Scanned Objects、YCB 物体集带关节的家具和器具，手能操作的日用物体还没有任务用到
3高质量 CC0 模型：Poly Haven家具、木箱、地面和墙面纹理H1 的柜子和折叠凳；H2、H3 的木箱和货架
4自建几何体找不到合适的素材，或者尺寸必须精确受控（比如台阶高度）H1 的地面箱

用第 4 级时要在任务卡里说明为什么前三级不合适。各素材库的许可证不同，逐个核对、记录。

素材要求

  • 来源和许可证：每个素材记录来源 URL、作者、许可证和改动（参照 H2 的 asset_sources.json）。许可证不允许再分发的，不进 git，用脚本下载。
  • 可复现：下载脚本固定版本并校验哈希（H2 记录了 SHA-256；Poly Haven 下载会校验 API 给出的 MD5）。
  • 真实尺度：按实物尺寸缩放，并写明缩放了什么。
  • 碰撞体和视觉网格一致：碰撞体用简化的盒子或凸分解，外形要和视觉网格足够一致。agent 用 RGB-D 看到的是视觉网格，物理用的是碰撞体；两者对不上，既是给 agent 挖坑，也可能被利用。
  • 物性真实：质量、摩擦、质心、转动惯量，有关节的还有阻尼、限位、回弹力，都取真实范围，并按第 04 节随机化。
  • 两个后端同一份素材：URDF / MJCF 与 USD 互转后，核对几何、质量和关节参数。
  • 外观不泄露用途：物体上不能有“STEP”“TOOL”之类的字样或特殊标记。颜色可以用来指认目标，但不能暗示用途。
  • “不可用”要在物理上真的不可用：不承重、会塌、固定在地上，都要由仿真实现（弱关节、低刚度、固定约束等），不能靠判据规定“用了也不算”。
  • 渲染开销可控：纹理分辨率够 RGB 感知即可（现有任务用 1K）。

04 · 初始状态随机化

能随机的都随机，不留固定起点和布局

对应 R8。

每个回合由私有种子决定。随机化让写死布局的程序拿不到分，迫使 agent 靠感知和闭环控制，也让多回合评分有统计意义。

随机什么

类别变量H1 现在的做法
机器人起点位置、朝向名义起点 ±0.15 m，朝向 ±0.3 rad
物体组成出现哪些物体、多少个柜子上 2–4 个彩色箱子；地上的箱子按任务类型必放，其余各以 50% 概率出现
物体位姿位置、朝向地面箱从 8 个候选点里选，再加 ±0.1 m 扰动，朝向 ±0.4 rad
目标是哪一个、放在哪里随机目标颜色、所在层和格位
家具型号、尺寸、层高3 个柜子型号，每个两套层高
物性质量、摩擦、质心地面箱质量按类型在 1–15 kg 之间，摩擦 0.3–0.8；30% 的回合里中号箱又轻又滑
身体参数力量、负载（在公开范围内）腿和手臂力矩上限 ×0.85–1.0，躯干加 0–5 kg
传感器噪声IMU 噪声取自 MJCF

三条约束

  1. 按证据标记实例。每个样本符合声明层和生成规则；分别记录完整成功证据、筛查通过、未确定、检查不通过。不要求逐个生成完整解；未找到解不能标为物理不可解。
  2. 不打开捷径。随机范围的边角上不能冒出绕开考点的解法，比如层高抽得太低、踮脚就够得到。范围边界要用 oracle 抽样实测（任务验收第 03 节）。
  3. 解题关键不能只靠真值得知。随机出来的隐藏物性，要能通过机器人传感器推断：推一下看要多大力，站上去看晃不晃，抬一下看关节力矩。

种子和数据划分

  • 用计数器式随机数，按（种子、环境编号、回合序号）取值：同一个回合在两个后端上、重跑时都完全一样。
  • 评测和评分模式下，种子由可信侧私下抽取，agent 拿不到。
  • 开发和评测用不同的种子集合；评分时按难度层（以及任务类型）分层抽样。

生成器怎么写

  • 先给所有候选物体抽好位置和物性，再按难度层决定放哪些（第 05 节）。这样同一个种子下，三层的必要工具完全一样。
  • 不满足约束的样本（重叠、够不着、违反层定义）用拒绝采样丢掉，规则写进任务卡，并记录拒绝率，避免分布被悄悄扭曲。
  • 子任务的起始状态也由同一个生成器（或检查点恢复）产生，同样随机（第 06 节）。

不随机什么

机器人模型和硬件上限（公开范围内的身体参数除外）、指令模板、公开的合规约束和阈值、仿真设置。

05 · 三层难度

只分三层，逐层叠加

对应 R9。

层场景里有什么考什么设计者要写明并验证
第 1 层
只有必要工具		目标，加上完成任务所需的工具和物体，没有多余的东西。发现物体能怎么用、怎么组合，并执行出来。每个物体为什么必要：去掉任何一个就做不成（用 oracle 验证）。
第 2 层
有用不了的工具		在第 1 层的基础上，加入本机器人用不了、但换一种身体就能用的工具或物体。agent 对自己身体的建模：身高、腿长、步高、手的大小和抓握宽度、关节力矩、负载、足底面积。每个物体换成哪种身体就能用（更高的人形、Go1 这样的四足、换一只手），本机器人为什么用不了，和别的物体组合也不行（组合后能用，就是另一条路线，按 R6 处理）；并用 oracle 实测本机器人确实用不了。
第 3 层
有干扰项		在第 2 层的基础上，加入干扰项：超出本机器人能力范围的物体或工具（太重、太高、太大、太窄），以及实际不可用的物体（不承重、一踩就翻、固定在地上、空心会塌、看着像把手其实是装饰）。排除看似有用的选项：做实验收集证据，失败后换路线。每个干扰项为什么用不了，以及机器人在投入之前能从哪个传感器读数发现这一点；不能只有读真值才知道。

规则

  • 逐层叠加，同一个种子。三层的目标、必要工具和它们的位置都相同，高一层只多放物体。这样成绩的差别能归到“认不认得出自己用不了的工具”和“排不排除得了干扰项”上。
  • 声明层单独留证。新增物体可能挡路或引入捷径。每个声明层／变体分别选代表完整参考，配合技能与实例筛查；不要求逐个随机实例完整运行。延期层明确列出（任务验收第 03 节）。
  • 多放的物体进特殊情况清单。它们可能被用出意想不到的用法（第 07 节）。
  • 不告诉 agent 层号。知道是第 1 层，就等于知道每个物体都有用。成绩按层分别报告。
  • 第 2 层与第 3 层的区别。第 2 层的每个物体都要指明一种能用它完成任务的身体，考的是自我建模；第 3 层的干扰项不需要这样的身体，考的是做实验、收集证据、排除选项。
  • 与 v5 的关系。这三层代替 v5 原来的 L0–L2 课程：看似有用的陷阱归入第 3 层，而且要给可获取的证据；物性变化、故障和噪声归入初始状态随机化。能力披露（explicit / partial / latent）是独立的一维，不算难度层。

举例：H1 需要一个垫脚箱的场景

层地上放什么
第 1 层一个高度够用的矮箱。
第 2 层再加一个高度合适、但重到 G1 推不动的箱子，放在离柜子远的地方（力量更大的机器人推得动）。
第 3 层再加高窄箱（太高爬不上、太窄站不住），和一个一踩就塌的空箱（尚未实现）。

06 · 子任务与课程

可拆分，能单独开始，保留课程学习的可能

对应 R10。

把任务设计成一条子任务依赖链。每个子任务有两样东西：

  • 用状态描述的完成条件。比如“一个能站人的箱子静止在柜子前”，而不是“推箱子”。这样不同做法都能满足，不规定唯一路线。子任务与过程计分的阶段一一对应（第 09 节）。
  • 能单独开始的起始状态。即前面的子任务都完成后的状态。来源有两种：由可信侧从 oracle 录制的检查点恢复（H1 沙箱已支持：恢复世界参数和全身快照，复现结果完全一致）；或者由生成器摆出物理上合法的状态再静置（不穿插、不悬空），同样随机。

举例：H1 的子任务链

子任务完成条件（状态）起始状态从哪来计分阶段
1 支撑物到位一只可用的箱子立正、静止在放置区 1 s（前沿离柜子 ≤0.15 m，与目标的横向偏差 ≤0.30 m）任务初始状态support_placed
2 站上支撑物双脚在箱顶站稳 2 s推完箱子的状态：可从 push_box 录制恢复on_support
3 取到目标目标比起始高 ≥3 cm 且在手边，保持 1 s站在箱顶的状态：可从 step_up 录制恢复target_reached、target_lifted
4 带着目标下来双脚回到地面，目标在手边、离地 ≥0.3 m，保持 1 s手持目标站在箱顶：还没有录制descended_holding
5 送到目标区目标静止在目标区 1 s，机器人没摔倒手持目标站在地上：还没有录制carried、delivered

H1 的 tool_engaged（动过箱子）是行为证据而不是状态，只作为过程分里的辅助阶段，不单独成为子任务。

两条课程轴

  • 难度层：第 1 层 → 第 2 层 → 第 3 层。
  • 子任务起点：从后往前，先练最后一步，再逐步拉长链条。

谁能用子任务场景

  • 子任务的起始状态本身就暴露了路线（比如“箱子已经在柜子前面”），等于给了指示。所以子任务场景只用于训练、诊断和分析，不对被评测的 agent 开放。
  • 评测始终从任务的初始状态出发；起点和难度层都由可信侧按评测计划决定，agent 不能选。
  • 以后如果开设使用子任务场景的课程赛道，成绩单独报告，不与主榜混合。

07 · 特殊情况

剔除捷径，合理的非常规解法照样给分

对应 R6。

流程

  1. 列出所有非常规路线。包括身体更高、能力更强时的直接做法，把干扰项换个用法，利用家具，单机代替协作，随机范围边角上的情况，以及高层多放的物体能带来的新路线。
  2. 分类。是绕开考点的捷径（让工具、前置条件或协作变得不必要），还是合理的非常规解法。
  3. 剔除捷径。用几何、质量、摩擦、布局或身体参数约束不允许的路线，并给出必要条件反例或针对性物理证据。一次搜索或尝试失败不能证明所有替代路线都不可能，必须记录验证范围（任务验收第 03 节）。
  4. 物理上剔除不了的，写进公开约束。比如“全程抱着箱子，不能放在台阶上”。
  5. 剩下的自动给分。判据只看状态、不规定路线，所以连续物理执行、遵守公开约束、通过全部完整性检查的非常规解法，达到哪些状态就自动拿哪些阶段的分；跳过的中间阶段不补发。设计时要确认合理的非常规解法也会经过这些状态。
  6. 漏掉的捷径。评测中被标记的回合暴露出本该剔除的捷径：记为设计缺陷，下个版本修复，所有 agent 用新版本自动重评。
漏洞不算解法：穿模、瞬移、能量异常、修改状态、钻判据空子，一律判无效（第 09 节）。

现有任务的特殊情况举例

10 · 设计自检

提交任务卡之前，逐条回答

场景和指令

  • 只看目标、按最直接的做法，为什么一定会失败？
  • 去掉某个物体后还能做吗？如果能，它就不属于第 1 层，要按第 2 层或第 3 层归类。
  • 把指令念一遍：有没有哪个词暗示了物体用途或路线？
  • 最强的 agent 大概要试多少个想法、经历多少次失败？如果不到 4 小时，难度从哪里加？

仿真和素材

  • 每个素材的来源、许可证、哈希都记录了吗？为什么没用更高优先级的素材？
  • 碰撞体和视觉外形一致吗？物性在真实范围内吗？
  • “不可用”的物体在物理上真的不可用吗？
  • 两个后端上同一回合的场景和结果一致吗？

随机化、分层、子任务

  • 边界和内部样本分别有哪些完整、技能或筛查证据？未确定范围是否明示？有没有打开捷径？
  • 第 2 层的每个物体：换成哪种身体就能用？本机器人为什么用不了，和别的物体组合也不行吗？
  • 第 3 层的每个干扰项：机器人在投入之前，能从哪个传感器读数发现它用不了？
  • 每个子任务能不能从自己的起始状态单独开始、单独判定？完成条件写的是状态还是动作？

可解性、验收、防绕过

  • agent 能从哪些传感器读数推断出物体能承重、能移动、够不够高？
  • 每个声明层／变体是否有预选代表性的完整见证？技能条件和实际段间衔接是否有证据？应审阅的代表录像是否已签审？
  • 列出所有你能想到的其他解法：哪些绕开了考点、要设计成走不通？哪些合理、要给分？
  • 站在攻击者的角度看每个阶段判据：不真正完成这一步，能不能骗到分？
  • 评分器把参考专家解判为成功、把空操作判为 0 吗？
  • 人看参考解和漏洞测试的录像，能不能按你的检查清单回答那三个问题？

攻击清单与反例集不能按第 09 节的类别列出可能的绕过手法；每个阶段判据的反例及其不得分的测试结果。

段落内容

[monitors]各类告警的阈值

本次状态落实：除 H1 外的 11 项任务

有完整成功证据／通过可行性筛查／未确定／检查不通过必须分开。检查器缺失或预算耗尽记未确定；检查不通过需必要条件反例与原因。自生成场景可按已验证技能范围采样；基准采样及所有结果完整保留。既有人工签审、第二人复现与评分器检查继续单列，不要求第二人逐个复现随机实例。
