CONTRIBUTE

从任务设计到可复核交付

八步贡献流程

  1. 设计任务。按任务设计的十一条硬要求写任务卡和机器可读的任务规格。产出：任务卡。这一步什么都不用实现。
  2. 设计评审。评审逐条核对十一条要求，重点看指令有没有暗示、直接做为什么不行、解是不是够非直观、特殊情况清单是否完整。产出：通过，或修改意见。
  3. 搭环境和场景生成器。Genesis（推荐同时对齐 Isaac Lab）、官方模型和素材、初始状态随机化、三层难度和子任务起始状态，做法见任务设计。产出：环境、素材脚本、场景生成器。 场景 scale up 按既定三级保留同种子对照；额外规模轴与延期层单列。
  4. 定义分阶段评分。按子目标规定前置依赖、实测判据、阈值、保持时长、权重与最终成功门槛，评测前冻结。产出：阶段评分表、可信评分器与正反例检查。
  5. 接入沙箱，做防绕过测试。逃逸探针、反例集、漏洞测试，空操作必须得 0，见隔离沙箱和评分与验证。产出：测试记录。
  6. 验证八项核心交付物。保留声明配置中至少一条完整专家见证，提交 high/low-level planning 与三向轨迹 mapping，核对阶段得分；分别完成物理与沙盒验证，并记录适用的人工审阅和未完成项。产出：专家轨迹、规划与映射、阶段评分、物理报告、沙盒报告；不要求每个随机实例都完整求解。 同时提交三级难度扩展与适用的 embodiment 能力边界对照设计及已有证据；未测项如实标注。
  7. 难度试跑。用标准 agent 配置按三层分别试解；如果第 3 层 4 小时内就解出来，就加深依赖、扩大随机范围，或者换更难分辨的干扰项（评测规程）。产出：每层的试跑记录。 按层报告成绩与开销；适用时固定世界和预算、逐项干预身体能力，并保留失败及未确定结果。
  8. 冻结、入库。评审核对提交清单上的全部材料。产出：带版本号、锚点和数据划分的冻结版本。

交付检查表

基础材料仍包括任务卡、初始场景与生成器、身体/传感器/动作规格、版本哈希和复现入口。最终指令只描述目标与约束；专家计划与可信侧证据不泄露给被测 agent。

交付项提交内容检查方式
一条代表性完整专家见证冻结场景、资产、物理、控制器与评分版本；提供生成程序、完整动作/状态/接触日志、录像、结果和哈希。从初态连续执行到最终成功；已有匹配版本的见证可以复用。至少一条仅证明声明配置，不证明全部随机实例。
High / low-level planning高层子目标与依赖图；低层技能/动作计划、参数、关键状态、进入/退出条件、接触/支撑约束及失效条件。能说明高层目标如何展开成可执行动作；未验证的技能适用范围留空，不把文字计划当成执行证据。
计划—轨迹三向 mapping每个子目标对应的低层段、轨迹起止时间/动作索引、关键状态、阶段条件、实测结果与证据文件。检查 high→low、low→轨迹、high→轨迹/目标达成。第三项可组合前两项并独立核验目标，不要求另写规划器。
分阶段评分阶段定义、前置依赖、可测判据、阈值、保持时长、权重、一次性/持续计分语义、最终成功与物理违规规则。评测前冻结；用可信测量重算阶段得分，并与轨迹时间线对齐。空操作得 0；阶段反例不得获得对应阶段分；违规或漏洞按冻结规则判 0 或 VOID。部分分不等于完整成功。 阶段分/进度、最终成功和 VOID 分别记录，违规处理按声明规程执行。
物理验证连续物理执行记录、接触与支撑/载荷检查、关节/力矩等约束、接口审计、独立动作回放及失败记录。禁止绕过动作接口的状态写入、运行时瞬移、强制附着、任意外力或理想状态恢复；任务预定义的物理结构与初态另列。静态初始化与局部诊断不替代完整轨迹。回放是否通过如实单列。
沙盒验证agent/可信侧分离、允许观测与动作、启动入口、SDK、隔离与越权探针、可信记录和重放校验。检查隐藏状态/评分器泄露和世界写入；接口短测与沙盒内完整专家执行分开报告。原生物理成功不自动证明沙盒通过。
场景难度 scale up（三级）提交 L1→L2→L3 的同种子场景差分、工具/干扰项清单、参数范围和逐层结果。L1 仅含必要工具；L2 每个新增工具指明能用它的替代身体；L3 干扰项说明失败原因及可通过传感器获取的线索。目标、必要工具和位置固定，高一层只增加物体；检查遮挡、碰撞、可解性与新增捷径。各声明层/变体留代表证据，延期层明确待验证。依赖链、工具组合、随机范围等规模变化另列，不能以延长录像或堆重复动作代替难度。 L1 保留工具必要性检查；L2 标出本体不可用与替代身体可用的证据或待验状态。若组合工具后可用，应记录为另一条合法路线。
Embodiment 能力边界（适用时）给出可实施的身体/末端/已验证控制器能力干预与对照计划；固定目标、世界、资源和预算，每次改变一个能力维度，并真实修改几何、动力学或控制配置。记录可达范围、夹爪开口、力矩/载荷、移动/平衡等约束及测量证据。 修改后重新验证物理与控制；给出测试点、可行/不可行/未确定边界及证据，不外推未测区间。分别记录必须换路线、只改变效率偏好、原路线仍可行、无可行解四类对照。单次失败不证明身体极限；排查物性、感知与控制误差。尚未实测的干预只标设计/待验证。单臂/双臂、固定/自由基座或不同机器人可作对照，但复合变化须单列，不能归因于某一个维度。

最低可行性见证为声明范围内至少一条连续完整成功轨迹，不要求每个随机实例都生成完整解。重复性、随机鲁棒性、适用的人工签审和第二人复现单列；已有预声明的有限验收批次继续保留。

专家生成过程可以使用如实声明的特权信息，特权参考不自动变成公共传感器策略。物理验证、原生动作回放、沙盒接口短测和沙盒内完整任务执行分别记录。

不要求

  • 只靠传感器、每次都成功的 oracle。
  • 真机实验。
  • 大规模训练；任务本身默认不训练。
  • Isaac Lab 对齐（推荐，但不强制）。
  • 指定唯一解法：只要合规，意外解法照样给分。

声明覆盖多个难度层或变体时，各声明范围分别留代表证据；尚未验证的层和身体对照标为待验证，不推断整个随机范围都可解。

职责与验收

角色负责
设计者写任务卡和机器可读的任务规格；搭环境和场景生成器；做参考专家解；人工验证可行性；写判据、反例和人工检查清单。任务入库后默认兼任维护者
评审设计评审；独立复现参考解；任务验收时做人工检查（看录像回答三个问题）；核对入库材料
任务维护者处理被标记的回合；修任务和评分器、发布新版本、触发自动重评；维护变更记录。在下一轮评测之前处理完
评测运营方保管私有材料（参考解、评分器、密封种子）；按评测规程组织评测、计量预算、公布成绩

许可与署名

  • 贡献的代码和文档按仓库约定的许可证发布。
  • 素材按各自的许可证使用，来源和许可证写进任务卡；许可证不明的素材不接受，不允许再分发的素材不进仓库，用脚本下载。
  • 任务卡和任务 README 写明设计者和评审；基于任务的论文或报告按此署名。
