02 · 评分器放在哪里、读什么

底线：评分器和计分与 agent 隔离

隔离到什么程度

  • 底线：评分器和计分与 agent 隔离，agent 读不到、改不了，也影响不了它们。本沙箱把它们放在环境一侧。
  • 评分器（verifier）、阶段判据、计分代码、密封回合的种子、锚点、参考解和录制，只存在于环境一侧，从不进 agent 的 bundle、镜像或工作目录。
  • 交付程序永远在 agent 容器里跑，只经 RPC 和环境通信，不进环境一侧。这比 Harbor（提交代码在 verifier 的文件系统上运行）和 EmbodiedSWE（提交代码与评分器同一进程）都更严格。
  • 评分结果（verdict.json）写在环境一侧的可信目录里；agent 在会话中拿不到任何分数，finish() 也不返回是否成功。

评分器读什么

只读环境一侧写下的记录：密封的场景文件、特权状态日志（每个控制步，含按物体记录的手、脚、其他部位接触力）、全身快照、回合事件、请求日志、监视器告警。agent 写的任何东西都只能通过这些记录间接体现，评分器不读 agent 的工作目录、输出或自述。

出错即判 0（fail-closed）

  • 没跑成的回合（程序崩溃、没连上、超时）记 0 分。
  • 评分器自身出错、记录缺失或损坏、结果不是有限值或不在 [0, 1] 内：该回合记 0 分，并写明原因。参照 Harbor 的 test.sh。
  • 任何完整性检查不通过：整次运行判无效（VOID），全部记 0 分。

两种部署方式（本机的宿主进程 / Linux 上独立的 env 容器）见隔离沙箱第 02 节。

03 · 阶段判据

判据只看物理状态，不接受单帧触发

阶段判据

  • 阶段与子任务一一对应（见任务设计第 06 节）；判据只看可信侧的状态日志，不看 agent 说了什么，也不看用什么方法做到的。
  • 每个判据都要求接触证据、物体身份、保持时长和静止条件，不接受单帧触发。
  • 只靠距离的判据要配合接触或运动证据。（H1 的 target_reached 现在允许“手离目标中心 ≤0.15 m”就算，不满足这一条，要改。）
  • 每个判据配一组反例（第 08 节），全部必须不得分。
  • 阈值在参考解的时间线和人工标注上校准（见任务验收第 03 节），评测前冻结。

04 · 计分与评分模式

按阶段连续给分，在密封的新回合上重跑

计分规则

  • 每个阶段在每个控制步上有一个 0–1 的连续值，表示做到了几成。
  • 两种模式：once 里程碑取迄今最好值；live 取当前值（比如目标被碰出目标区就掉分）。
  • 进度(t) = Σ 权重 × 阶段值(t) / Σ 权重；回合得分取整个回合中进度的峰值。
  • 是否成功（0/1）单独给出，与 Terminal-Bench 的口径一致。
  • 本回合拿不到的阶段（只看初始状态判断）去掉，权重重新归一。
  • 摔倒或声明会结束回合，之前的进度保留；对可解的回合声明不可行，单独标记。
  • 整次运行判为无效（VOID），得分记 0。

评分模式和报告

  • 正式成绩来自交付程序在 N 个密封新回合上的重跑，不看开发会话；每个回合评分 3 次取平均，整个评测重复 3 次（见评测规程第 04 节）。
  • 报告什么、怎么汇总，见评测规程第 03 节。

H1 的阶段、权重和取值见 H1 沙箱 README 第 5.3–5.6 节；权重还没有用真实 agent 的结果校准。

05 · 自动评分规则

评测 agent 全自动，告警按规则处理

评测 agent 时不看录像、不手工改分：verifier 的结论就是成绩，各类告警按下表自动处理。人工检查只针对任务，在任务验收时做（任务验收第 05 节）。

情况自动怎么处理
完整性报警：越权调用、世界参数被改、瞬移、场景未密封就连上整次运行判无效（VOID），记 0
物理异常：穿透过深、物体速度或动能突变、物体出界或穿过地面异常时间窗内拿到的阶段分不计；超过严重阈值的，整次判无效
指令模式和判据异常：高频抖动、长时间力矩饱和、阶段值单帧跳满、没有接触证据的阶段值相关时间窗内的阶段分不计，并标记
编造：rollout 来源核对不上；得分却从不读传感器前者整次判无效；后者得分不计，并标记
没跑成、评分器出错、结果不是有限值或不在 [0, 1] 内该回合记 0，写明原因
同一回合 3 次评分的差别超过容差取三次平均计分，标记为“不可复现”，交维护者修任务
合理的非常规解法按达到的状态给分，跳过的阶段不补发（任务设计第 07 节）
拿不准的情况一律按对 agent 不利的一侧自动处理，并标记；不交人逐个裁决

处理规则和阈值在评测前冻结。被标记的回合汇总给任务维护者：如果它们暴露出评分器的漏洞、仿真器的问题或漏掉的捷径，就修改任务、发布新版本，再用新版本把所有 agent 自动重评一遍；不手工改某个回合的分。

verifier 和计分要做的调整

  • 告警按三个问题分类输出，附上时间点和可信日志片段：评测时用来自动处理和标记，任务检查时让人直接跳到对应位置。
  • 每类告警都有写死的自动处理规则（上表），评测前冻结；拿不准的一律保守处理。
  • 报告给出自动分、被标记的回合和原因；没有人工改分这一步。
  • 任务或评分器改版后，所有 agent 用新版本自动重评。

06 · 监视器：防 reward hacking

在环境一侧在线盯着

监视器都在环境一侧运行，告警写进可信目录，由评分器读取。毫无歧义的告警直接判无效；可能是正常控制的告警按冻结的规则自动处理：相关时间窗内的阶段分不计，并在报告里标记（第 05 节）。阈值在评测前冻结。每个监视器都要有两组测试：漏洞手法的运行必须触发，oracle 运行不能误触发。

监视器看什么
接口未知方法、错误令牌、畸形帧、开发模式之外的 reset
世界完整性场景在 agent 连上前是否已密封；质量和摩擦每 500 步哈希核对；瞬移（>20 m/s）
物理异常穿透深度；物体最大速度；动能突增、且和机器人做的功对不上；物体出界或穿过地面
指令模式高频抖动（给物体注入能量的常见手法）、长时间力矩饱和、持续顶在关节限位
判据异常阶段值在单帧内跳满；没有接触证据的阶段得分；进度突跳后马上回落
资源和时间墙钟预算、仿真时长、观测次数；容器的进程数、内存、CPU
网络内部网络之外的连接尝试；代理拒绝的请求
录像环境一侧录的俯视录像（以后加机载相机画面）

07 · 防止编造输出和输入

只信环境一侧的记录

原则：agent 说了什么、写了什么文件，都不是证据；证据只有环境一侧亲手记下的东西。下表分别列出编造输出和编造输入的情况。

编造什么例子防护
编造结果在最终报告里声称成功，或给出不实的阶段完成时间分数只来自环境侧记录，不读 agent 的任何自述。如果要求 agent 提交报告，可信侧拿报告和记录逐条对照，不一致的记为“编造”并报告
伪造文件在工作目录里写假的评分结果、日志、录像或分数评分器只读环境侧的可信目录；agent 容器只挂载工作目录；任务检查只看环境录的视频
伪造对话和开销改写自己的对话记录、少报 token 用量agent 的标准输出由启动器在容器外记录；LLM 请求和 token 计数应由可信侧的代理独立记录，不用 agent 自己的统计
伪造 RPC 请求冒用会话、伪造帧、重放旧请求会话令牌（常数时间比较）、长度前缀 JSON、不用 pickle、一次只服务一个会话。请求日志升级为哈希链（每条记录带上一条的哈希），并记下每次观测的摘要，事后任何关于“看到了什么、做了什么”的说法都能核对
伪造观测交付程序不读传感器，回放开发时录下的观测或写死的轨迹（开环）初始状态随机，评分回合和开发回合用不同的种子，开环程序拿不到分。监视器统计每个回合的 observe 调用；从不读传感器却拿到分的回合，得分不计并标记
伪造 rollout 或技能来源把参考解、官方轨迹或别处来的轨迹冒充成自己的 rollout；用清单以外的技能技能只认任务卡和 agent 登记清单里的；rollout 引用环境发出的观测摘要，评分前逐条和请求日志核对；网络隔离挡住下载
伪造评分输入往评分器读取的文件里写东西评分器只读环境侧写下的文件，agent 碰不到那个目录
冒充启动器发出“换下一回合”或“关闭”控制管道是 worker 的标准输入，只有启动器持有，不经过网络

08 · 攻击类型与防护

默认不信任：证据确凿才给分

对应任务设计指南的 R7：设计者按下表的类别写攻击清单，并交付反例集和漏洞测试（见任务设计第 09 节）。

有效成功 = 目标达成 ∧ 约定满足 ∧ 完整性通过（v5 第 15 节）。阈值、时间窗、容差和异常处理在评测前冻结。下表每一类都要在任务设计时给出防护，并在验收时拿出证据。评测全自动；人工只在任务验收时检查（任务验收第 05 节）。

攻击类型例子设计时必须做的防护验收证据
读到不该读的信息读可信侧文件、种子、难度层、参考解、计分脚本；联网拉仓库历史；从观测向量里拿物体位姿；从错误信息或状态里得知是否成功；把参考解、官方轨迹冒充成自己的 rolloutagent 只在容器里，bundle 里没有可信侧内容；网络只放行仿真端口和 LLM API；观测只有机器人传感器，不透露难度层；不向 agent 返回分数或成功判定；技能只认指定来源，rollout 和请求日志里的观测摘要逐条核对静态 bundle 检查、容器逃逸探针、请求日志
越权改世界调用 setter、瞬移、改质量摩擦或物理选项、开发模式外 reset、把物体绑在手上；评测时自选子任务起点或难度层只开放白名单接口；起点和难度层只由可信侧按评测计划决定；世界开局密封；指令只作用于关节并按硬件上限截断；世界参数哈希核对逃逸探针全部被拒并记为违规；参数哈希不变；无瞬移
仿真漏洞穿模、穿墙、高频抖动关节给物体注入能量把它弹飞、利用接触求解异常卡进物体里“爬”上去、自碰撞关闭；碰撞体与视觉外形不一致处的漏洞物理选项固定；碰撞体与视觉外形核对一致；verifier 检查瞬移、穿透深度、物体最大速度和能量突变；设计者亲自试一遍常见漏洞手法（高频抖动、顶墙、压进物体）并确认被判无效漏洞手法的测试运行判为无效；任务检查时人工看录像
钻阶段判据的空子手在目标旁边晃一下就算“碰到”；把目标抛过目标区、只经过一帧；把目标撞飞到空中算“取下”；错的物体进了目标区；拿脚蹭一下箱子算“用了工具”每个判据都要求接触证据、物体身份、保持时长和静止条件，不接受单帧触发；只靠距离的判据要配合接触或运动证据；进度峰值只用已经保持住的值每个阶段一组反例（合成日志加录制运行），都必须不得分；人工标注与判据对照
钻计分规则的空子先拿几步分再提前声明不可行；反复触发同一阶段；从被钻空子的目标阶段倒推，补齐前面的分声明会结束回合，声明错误要单独标记；每个阶段只计一次；跳过的中间阶段一律不补发；去掉阶段只看初始状态，agent 无法影响计分单元测试覆盖这些情况
钻评分模式的空子把开发回合的布局写死在程序里；通过文件把信息带到下一个评分回合；探测自己是不是在被评分初始状态大范围随机；评分回合用私有种子，与开发回合分属不同的数据划分，并按层分层抽样；每个回合给全新的程序副本，不留任何状态；开发模式和评分模式的接口与观测一致评分回合与开发回合布局不同；跨回合没有残留文件
绕开考点的捷径见任务设计第 07 节：踮脚够取、爬家具、单机完成协作任务；随机范围边角上冒出来的捷径；高层多放的物体被拿来绕开考点设计时让它在物理上走不通，或写进公开约束；用 oracle 手段逐条试过，覆盖随机范围的边界和每一层人工确认的捷径排查记录

可疑运行怎么处理

  • 任何完整性检查报警：整次运行自动判无效（VOID），得分记 0。
  • 其他告警按第 05 节的规则自动处理：相关阶段分不计，并标记。
  • 被标记的回合汇总给任务维护者；查出漏洞或漏掉的捷径，就把手法加进反例集、修判据或监视器，发布新版本，所有 agent 自动重评。
  • 不对单个回合人工改分。
