Task infrastructure · Implementation status

The specifications live on the other pages;
this one records where the implementation stands.

All 14 current tasks have a unified launch entry; Sokoban uses per-robot isolation. Earlier implementation records below retain their historical scope; use the ledger above for current coverage. H1 (G1 support-assisted retrieval) is the reference implementation of the whole infrastructure. Since 2026-10-21 the task-independent runtime (protocol, worker, launcher, containers, command channel, sensors, record format, monitors, verifier wrapper, admission records) lives in infra/sandbox/ and is shared by H1, H2, H3, H4, H6, M2, M4 and the two tabletop tasks (Hanoi, sleeve and cap assembly); the rows below describe that shared runtime unless they name H1. Below is the status of every item by page, then the progress of the H1 task itself, the verification done so far, the merged, de-duplicated to-do list, and where each task stands on the 15 acceptance gates.

02 · The H1 task itself

Where G1 support-assisted retrieval stands

  • Environment: implemented in Genesis and Isaac Lab, plugged into the sandbox.
  • Reference expert: Frozen C371 passes all three original-start native attempts (3/3; 1003.36, 1003.16, 1004.16 s). Matching C373 passes the actual-container LowCmd run (1003.12 s). All four score 1.0, are non-VOID and have no safety events; LowCmd has zero clipping. Frozen sources and initial scenes match. Release packet verified and ready; not uploaded remotely. Privileged state, disabled self-collision and elevated final release remain disclosed; the historical canonical c rule-5 failure remains preserved. Validation record
  • Official stage trajectories: push 4/4, stool carry 4/4, step up 5/5, box carry 5/5. The full chain with a support is completed by the reference expert; see the previous item.
  • Process-score anchors: relay c provides a physical positive for all nine stages; three-layer no-op and low-pelvis fall controls score zero. Legacy step_up 0.25 and push_box 0.33 use a different rule version.
  • Difficulty layers: relay v2.1 implements a nested three-layer generator, separate from the legacy five-family environment. Randomization boundaries and per-layer feasibility still need physical expert trials.
  • Corner cases: reaching on tiptoe, climbing the cabinet's lower shelf and laying the tall narrow box flat as a step count as success when done safely (author decision 2026-10-21); direct-v8 secured the target from the floor but slipped during extraction and did not deliver; the other routes still need physical probes. Safety rules for every route: a fall or near-fall, an unstable standing support, body weight on the cabinet, a release with the box bottom above 0.8 m or the box moving faster than 1.0 m/s, or sustained actuator saturation makes success false. Implemented as relay-rubric/2.2 and calibrated on the existing recordings. Canonical c now fails rule 5 (waist at its torque limit for 4.5 s and 6.1 s); the author kept the rule, and the expert is to be changed and re-run.
  • Predicates: relay v2.1 uses actual contact, support loads, geometry and continuous evidence, not hand distance alone. Goal success_rate is primary; process weights still lack real-agent calibration. Elevated release and stable side-lying are allowed.
  • Automatic checks: static checks, scoring unit tests, escape probes and sensor geometry checks exist, but are not yet chained into a pipeline that runs on every change.

H4 · 2026-10-21 update: four design decisions confirmed

  • The long plank is 4 cm thick (v4.1; the original task.json says 6 cm, the graded scene is scene.py). At 6 cm the G1, with the box hanging at its side, fell or ran off the plank end in 11 of 20 step-ups; at 4 cm in none of 4.
  • A target with a handle counts as held with one hand in contact; a plain box still needs both hands. "Lifted" uses the target's lowest point, so standing the box on its end is not a lift.
  • The layer-3 short plank and the 45 kg heavy board no longer interpenetrate at the start (v4.2); the energy monitor found the defect.
  • The monitor rules, handling and thresholds (h4-monitors/2).

H4 therefore has no open decisions, and the reference-expert gate is now passed (6 / 15). Not yet done: shortcut audit, video review (needs a signature), independent reproduction. Partial: coverage (range edges not targeted), re-run spread (Genesis on the GPU is not bitwise reproducible; the same seed run twice changed outcome in 5 of 14 pairs, so each episode needs 3 grading runs), stage labels, randomisation, automatic pipeline (the checks are chained and pass on the cpu and container tiers; nothing triggers them automatically yet).
