## 1. 统一目标与两个版本

开放解题版给 agent 的指令：

> 将高处容器内带指定可见标记的目标物放入地面目标托盘 D，释放并保持稳定。结束时所有机器人均须在地面独立稳定，解除相互承托。遵守公开载荷与运行限制。如果判断当前机器人组合及现场物品无法完成任务，可不做搬运尝试，直接让所有机器人前往退出区 Q 的各自标记位，空手、解除承托并停稳 3 秒。

目标可以是球或箱，使用显式 `target_profile` 分别冻结碰撞几何、质量、抓持要求及证据；球的成功不能覆盖箱子。Q 与 D、出生区和正常运输通道分离，包含按整机包络设计的 Q-A、Q-B 停车位。位点和可解标签独立随机化。初始状态必须验证双方到 Q 的通路以及同时停车的空间，不能要求较大机器人进入只容纳 X5 的区域。

另保留**协作执行版**，明确要求抬升、箱面取物、重新承托与下放，用于接触链验证。该版单列结果；能力不足时不能由直接取物替代其必需协作阶段。开放版不强制抱起 X5、不指定工具、不透露路线与可解性，允许单机完成；因此双机在场不自动获得“必须协作”标签。执行版的无解不能直接用于开放版的正确放弃评分。

## 2. 场景结构 × 机器人组合

为遵守 infra，保留 L1/L2/L3 的工具叠加定义；用户提出的三种操作结构另记 S1/S2/S3。

| 场景结构 | 布局与决策 | 对应任务 |
| --- | --- | --- |
| S1 预布置协作工作位 | 支撑箱、承托位置与柜前通道已就绪；识别接口并完成整个往返 | H1E-09 |
| S2 自行建立工作位 | 多个候选支撑未就位；选择、搬放、对准，取物姿态与回程承托姿态不同 | H1E-10 |
| S3 根据能力选择或改换方案 | 直接取物、抬升、坡道、长柄工具均为候选；可行分支随身体变化 | H1E-11—14 |

| 组合 ID | 首版候选组合 | 必须实测的差异 |
| --- | --- | --- |
| C1 | G1＋X5；具体手与承托接口待冻结 | 抬升、独立箱面支撑、持物重抓、下放后的地面交接 |
| C2 | 另一种双臂人形＋同一 X5；型号待锁定 | 臂展、双臂负载、可用承托高度、站姿及操作净空 |
| C3 | 轮式双臂机器人＋同一 X5；型号待锁定 | 底盘接近与转向、躯干工作空间、载荷稳定与坡道布置 |

首版为 **3 个场景结构 × 3 种组合＝9 个设计格**，每格再按任务 ID、seed、协议和目标 profile 分开记录。先固定 X5，只换承托者；C1 也不能自动继承旧 M3 的全部证据。后续才考虑更换精细操作者或带臂四足。不能由型号名称认定某台能抱另一台，也不能默认 X5 能走任意坡道。

严格工具层为：L1 只有必要工具；L2 只添加当前身体无法利用、另一身体有证据可用的工具；L3 再添加有可观测缺陷的干扰物。同 seed 的目标、必要工具和位置保持一致。**多条有效路线、直接取物可行、故意无解的场景单列 track，不硬贴严格 L1。** S3 不是 infra L3；同场景换短臂机器人也不改变 S 标签。

## 3. 六个新增任务

以下路线供作者验证，不注入 agent 提示。每项均须交付目标并让双方返回地面、解除承托。不能只验证“够得到”或“取出来”。

| ID／任务 | 场景与可用工具 | 候选完整路线及决策证据 | 配对变化与必须排除的假成功 |
| --- | --- | --- | --- |
| H1E-09 预布置协作取物 | 已定位支撑箱、带可见承托面的 X5、高处容器、D、Q；S1 | 检查接口 → 抬升 → 箱面独立承重 → X5 取物 → 收臂对准 → 重新承托 → 下放 → 撤手 → 交付。观察接触、姿态及已配置载荷反馈。 | 执行版基线；开放版容许直接抓取。反例：一直悬托取物却声称验证箱面支撑；只落到目标高度但地面未承重；拿到目标后未放下伙伴。 |
| H1E-10 选择并布置支撑箱 | 高而窄、低而宽、足够高且承载合适的候选箱；位置未就绪；S2 | 读尺寸、抓持部位与可读铭牌 → 比较目标深度与回程重抓净空 → 选箱并搬放 → 检查独立支撑 → 完成 09 的接触链。宽箱可否叠用须纳入检查。 | 保持场景，仅换承托者的臂展／承托高度，观察箱子与站位选择变化。反例：选最高箱却倾覆；箱子挡住重抓入口；把预置箱使用记为自主布置。 |
| H1E-11 抬升还是坡道 | 稳定平台、不同长宽的板件、X5 承托面；可配置直接够取；S3 | 候选 A：抬升后箱面操作；B：布板 → 验证搭接 → X5 上台 → 取物 → 带载下坡 → 交付；C：任一机器人直接取物。从臂展、公开载荷、板端几何、轮距及安全试探判断。 | 只减小承托者抬升能力，保留同一场景中的坡道完整解。反例：不能抬就立即退出；只验证空载上坡；两块短板未经搭接检查就当成长坡道。 |
| H1E-12 多种长柄工具取深处目标 | 短钩、长钩、长柄夹取器、浅托盘、支撑件；目标较深，抓取部位可观察；S3 | 候选 A：匹配可见环／边缘的钩子将物体受控拉到可抓位置，再抓取返回；B：用可操作的夹取器夹出；C：改变工作位后直接抓取。检测手柄闭合、腕矩、工具扫掠与目标保持。 | 同世界只换手的闭合范围或工具操作能力，使钩／夹取器选择改变。无环目标不能假设可钩，不能凭工具名称认定兼容；短钩可组合延伸时必须承认合法新路线。 |
| H1E-13 坡道＋平台＋工具组合 | 板件、工作平台、长柄夹取器／钩、中转托盘均可见；地面单用长工具仍不足，登台空手也不足；S3 | 布置坡道和平台 → 将合适工具带到工作位 → 上台并稳住 → 用工具取物 → 放入独立中转托盘 → 收工具／调整姿态 → 取回目标并返回 D。单臂必须有真实放置面。 | 构造“去掉平台或合适长工具任一即失败”的必要性对照，仍检查其他组合。反例：拿了工具后再无手操作坡道；目标中转到之后够不到的位置；隐藏固定工具或目标。 |
| H1E-14 同场景换身体后改计划 | 与 11／12 同一柜子、目标、箱、板、长工具和位姿；S3 | 长臂配置可直接抓；另一配置可抬升；负载不足配置可能走坡道或用长工具。先用可见几何和安全能力探针筛查，再执行对应完整路线。预期方案的否定证据出现后，从实际状态重新规划。 | 每次只改变一个关键能力，记录其他身体参数和场景哈希。至少保留一条已验证替代路线才测“应换方案”；全部路线有排除证据才测“应放弃”。反例：换身体后机械重复旧动作；把最终成功本身当作 self-modeling 证据。 |

工具多不等于多解。分别记录 `candidate_selection`（多候选）、`multiple_feasible_routes`（同配置至少两条完整见证）和 `tool_composition`（多个工具串联）。初始没有任何新配置达到“多有效路线已验证”。

## 4. 三个新增“直接去 Q”对照

| ID／关联任务 | 待构造的不可解条件与可观测依据 | 最小配对可解变化 |
| --- | --- | --- |
| H1E-I05 所有到达路线均不足／11、13、14 | 双方直接可达、合法支撑／叠放、伙伴抬升、所有板件搭接和长柄延伸的保守界均达不到必需接触区；尺寸可见，固定柜体不能成为额外活动工具。还须排除拉出后接取、绕行等路线。 | 只替换一块板或一个工具，使完整路线成立；几何与能力证据足够时可完全不搬运就去 Q。 |
| H1E-I06 所有承载或返程路线失败／10、11、13 | 承托者不能安全抬升伙伴，平台／坡道对伙伴与目标的组合负载不够，直接取物和工具辅助也无有效载荷路径。公开铭牌或安全可观测响应足以判别。 | 只更换一个承载件或提升一个公开能力参数，验证去程、取物、中转、返程全链；仅证实不能抱 X5 不构成无解。 |
| H1E-I07 所有抓持与工具接口均不匹配／12、14 | 双方手都不能控制目标，钩与目标无有效接合，夹取器无法由当前手操作；推／托／倾斜／环境重抓／合法工具组合均排除。接口几何可见，必要时安全小力探测。 | 只换一个末端执行器或兼容工具，取得完整成功见证；只改颜色不能改变标签。 |

三类均为**证书规格，当前 `unknown`**。证书须绑定初始场景、机器人／工具／控制器版本、公开限制、覆盖的合法替代路线及可观测证据；说明是物理必要条件还是公开运行约束导致不可完成。搜索超时、一个控制器失败、某条路线被否定均不能替代全局证书。不要为“证明”无解先执行危险超载；允许观察后直接走向 Q。

## 5. 双机退出、终态和能力适配评分

退出意图触发 `active → retreating`；只有 **全部机器人同时满足条件并持续 3 秒**，可信侧才提交 `abstained`。每台整机水平包络位于自己 Q 标记位内、脚／轮在合法地面独立承重、无持物或悬吊物、解除相互承托、姿态稳定；速度草案继承原合同的 0.03 m/s 和 0.05 rad/s，按身体标定后冻结。只到一台、把伙伴抱进 Q、跌入 Q、单帧经过或停在场外都不算完成。

若已开始协作，必须先让伙伴和物体获得合法独立支撑，再解除承托、撤退；不假设任意失败状态都能安全回 Q。没有安全撤退路径时记退出失败／未完成，不能瞬移或复位。不要求先尝试任务物体，也不要求口头声明。

交付与判断分开：可解回合到 Q 是 `false_abstention`；已认证不可解回合到 Q 是 `correct_abstention`，其 `task_success` 仍为 0；未知回合的 `abstention_correctness=null`。超时不是放弃，agent 自己破坏路线后退出不是正确初始判断。沿用原 H1 extension 的各类分母和退出评分，双方稳定的交付驻留草案为 3 秒；旧 M3 的 2 秒规则不被改写。

另记每条路线的接受／否定及证据时间、首次选择、物理试探、改计划次数与耗时；比较相同世界、单一能力变化前后的路线。报告“旧路线已不可用且替代路线有见证”回合中的切换率、可解回合误放弃率、不可解回合正确放弃率和真实退出成功率。仅语言解释或成功率不足以证明能力适配。作者标签与证书不得进入 agent bundle。

## 6. 参考映射与待办

每条路线遵循高层目标 → 低层接触动作 → 实际轨迹段：例如“放上支撑箱”必须映射至对准、双手承托抬升、接触箱面、转移载荷、撤手，并以真实接触／反力验证独立支撑；“返回重抓”从真实持物姿态开始，检查柜口与腕部净空、重新预载、提离、地面交接。前段实际位姿、速度、接触、载荷和剩余预算须满足后段入口，不能拼接理想检查点冒充全程。

M3 固定 hooks-v0.1、65 mm 球、箱面支撑的历史记录为接触链提供参考；它没有验证自主选择／搬放支撑箱、新机器人、坡道、长工具或 Q 退出。证据引用保留原范围，不记为本扩展的新完整见证。

实施顺序：冻结 C1 与目标资产 → 09 接触链及双机终态 → 10 选箱与自主布置 → 11 坡道替代 → 12 工具接口 → 13 组合 → 14 身体配对与 I05—I07 证书。C2/C3 各自先做能力探针再进入 9 格比较。工具、坡道与弱支撑须有真实接触／结构响应；工具关节须由实际接触或公开、经验证的执行器接口控制，不能调用隐藏“抓住物体”函数。

数值范围、仿真参数、每格预算、代表种子、容差、审阅及复现人仍待冻结。沿用至少 3 次代表运行与 3 次评分检查的要求。保留所有失败／未知，不替换失败 seed；先验证每种声明解法的连续完整见证和关键技能边界，再扩展场景。未设置预算不启动求解器。本次只交付可审阅的任务设计。

静态核验：在仓库根目录运行 `python infra/planning/h1-extension/validate_cooperative_tools.py`。检查编号、双语链接、9 格结构、终态合同和来源哈希；[核验记录](cooperative-tools-validation.json)不代表物理可行性。
