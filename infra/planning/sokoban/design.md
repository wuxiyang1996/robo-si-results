# Sokoban：从局部观察到全局建图

设计版本：2026-10-29 · 状态：正式验收准备与连续物理验证进行中

[本轮验收准备、检查清单与全部尝试](../../task-sokoban-acceptance-zh.html) · [此前专家规划、轨迹与视频](../../task-sokoban-progress-zh.html)。下文定义任务目标；执行状态以逐项证据为准。

核心问题：多机器人能否从各自的局部观察构建一致、可更新的全局地图，并利用地图完成推箱清路？通信是否改善建图与执行？Agent 能否按需编写有用的建图、融合或规划工具？

## 1. 任务与边界

两台机器人在包含墙体、通道和可移动箱子的场景中探索，推动箱子清理道路，最终同时在各自目标区稳定驻留。箱子没有交付目标。首版采用 G1 + G1。

- **输入**：自身局部 RGB、关节与惯性观测、自身目标标识；开启通信时，可接收同伴显式消息。
- **隐藏信息**：完整地图、箱体真值位姿、同伴隐藏状态和评测反馈。全局真值只供环境与评测使用。
- **动作**：通过控制器驱动真实物理接触；箱子只能推，不能抓、拉、抬或通过状态写入移动。
- **成功**：两机到达各自目标并满足驻留、稳定性与物理合法性条件。沿用 L1 原生 2 秒同时驻留要求；新等级具体参数须在评测前冻结。
- **全局建图**：将多个局部视角连接为一致的空间表示，区分已知与未知，并在箱子移动后更新可通行性。地图可为栅格、拓扑图或其他可查询表示，不限定实现算法。

“全局”指机器人构建的环境理解，不是提供俯视图或完整真值。保留并公开当前感知假设，例如已知网格间距、平地和颜色编码；取消这些假设需另设实验。

## 3. 通信与工具：两个独立实验因素

| 条件 | 信息与权限 | 用途 |
| --- | --- | --- |
| C+：显式通信 | 私有工作区与局部观测；允许受限消息 | 测量共享地图证据、协调探索与分工的收益 |
| C−：无显式通信 | 相同输入与预算，关闭消息接口；仍可看见同伴动作 | 测量独立建图与隐式协调表现 |
| 自建工具：主设置 | 两种通信条件均允许在私有沙盒内编写、运行程序 | 观察 agent 是否按需构建地图、融合器、路径规划器或协议 |
| 固定工具集：可选消融 | 两组提供同一预先冻结的工具集，限制新增可执行工具；保留正常策略推理 | 单独研究自主工具构建的价值 |

通信不直接生成工具。C+ 可以通过消息传递地图片段、接口约定或代码文本；所有传输均计入消息预算，不增加共享文件系统或隐藏通道。C− 仍能在自身工作区独立构建工具。

主通信对照必须保持工具权限一致；否则无法区分通信与编程权限的影响。固定工具集消融需先定义可执行工具与策略状态的边界，未能一致执行该边界时不报告工具构建的因果结论。

实体工具不属于核心任务，也不是通关要求。长推杆等只作为未来可选扩展，不作为 SK-L3 的定义。工具数量、代码长度或调用次数不直接加分；记录工具创建、实际调用及对应结果，是否有效由配对对照验证。

## 4. 实例设计

首批 L2 使用三个可解释的实例族，再扩充随机覆盖：

1. **信息互补**：两机初始视野覆盖不同分支；一方发现的死路或通道能帮助另一方减少重复探索。
2. **共享瓶颈**：箱子阻塞关键通路，一方清路会改变另一方的可达区域，需要更新地图和执行顺序。
3. **动态恢复**：推动后通路改变、箱子偏离预期或局部计划失效，需要重新观察和规划。

每个实例固定地图、箱子初态、起终点、物性、能力配置和随机种子。按拓扑族划分开发与测试集，避免仅换种子造成布局泄漏。先检查静态连通性和符号计划，再筛查机器人扫掠空间、推动姿态与物理可行性；代表实例保留完整执行见证。

保留所有生成和筛查结果，分别记录完整见证、筛查通过、未知和检查失败。搜索超时不等于不可行。机器人到达任务中，把箱子推入角落可能是在清路，不能直接套用传统箱子归位任务的死锁规则。

## 5. 评测：三条主线

| 主线 | 指标 | 解释边界 |
| --- | --- | --- |
| 地图是否正确 | 已知区域覆盖、占据/通路判断、跨区域连通性、推箱后更新延迟 | 同时报覆盖与准确性；未知不能当作空地，也不能只报已知区域准确率 |
| 任务是否完成 | 物理合法的双机到达成功率；耗时、无效推动、恢复成功率 | 到达与物理有效性分别记录；证据缺失为未知，不计作合法成功 |
| 通信是否有益 | 同一实例 C+ 与 C− 的建图质量、成功率和完成成本差值；消息字节数 | 配对运行，多种子汇总并报告不确定性；消息多不等于协作有效 |

当前实现按固定时间间隔保存 agent 地图快照，包含时间、坐标约定和已知格点，并以固定初始坐标变换事后比较覆盖、占据与可通行性。只评测 agent 实际生成的规划地图。现已增加固定非墙格点对的连通性查询，以及箱体换格后的地图更新延迟。连通性分别报告回答覆盖、已回答准确率、误连通和误断开；未观测到更新的事件保留为截尾结果。评估针对当前栅格原型，通用拓扑表示适配仍待后续实现。

地图只做事后真值对齐，不能把对齐结果返回 agent。每段轨迹使用同一坐标变换，避免逐帧重新对齐掩盖漂移。预先固定评测区域与查询集合，分别报告每台机器人的地图；共享地图仅在 agent 实际构建并提交时评测，不能由评测器自动融合后当作 agent 成果。

全图覆盖作为诊断，不强制为了拿分探索与目标无关的每个角落。任务成功仍按合法到达判定，不将建图指标临时加到历史 L1 分数。首版不做单机对照，避免移除机器人后改变双机目标定义。
