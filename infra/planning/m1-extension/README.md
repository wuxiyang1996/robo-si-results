## 1. 身体配置与三档决策难度

| 配置 | 目标身体组合 | 真正需要改变的决策 |
| --- | --- | --- |
| A | G1＋Dex3，搭配 X5 移动臂 | 大尺度搬箱与低位交付的分工；原见证须核对具体资产、手、控制器后才能复用 |
| B | 同一 G1 更换五指灵巧手，搭配同一 X5 | 抓持宽度、接触几何、控制接口与持物能力；不预设五指手更强 |
| C | 轮式双臂机器人＋低位操作机器人 | 靠近货架的方式、升降／双臂工作空间、搬箱与交接高度；型号待模型和控制器核验 |
| D（后续） | 单臂移动机器人＋环境工具 | 是否可直接取块、分步转移或借助外部支撑；不能默认具备双臂搬箱能力 |

R1、A3、Stretch、Go1＋机械臂仅为后续资产候选，不据品牌或外形分配可行路线。传感器与末端配置必须逐个锁定。

| 决策档位 | 信息与环境 | 要测的决策 |
| --- | --- | --- |
| Easy | 准确的身体能力说明和接口；合适的交接面已经就位 | 根据已知能力分工，完成并调试连续程序；说明不能包含场景真值或参考步骤 |
| Medium | 基础接口和公开安全限制；负载能力、实际可达域需查询或安全探测；末端／关节配置或交接位置变化 | 发现当前身体能力，调整抓持、站位、交接高度或交付者 |
| Hard | 直接路线不可行，必须选择并布置现场物品；多件候选物中有不适配项 | 根据身体限制改变环境，建立新的支撑、运输或取物链 |

这里的 Easy／Medium／Hard 是 **M1 扩展决策档位**，不是现有“第一层 CPU 特权参考”的交付标签，也不替代规范的工具层 L1–L3。规范仍是：L1 仅必要工具；L2 增加当前身体不能用、指定另一身体能用的工具；L3 再加可观察的不适配／物性干扰。各层同 seed 保持目标、必要工具及其位姿，逐层只增加物体并复查捷径和遮挡。能力披露 explicit／partial／latent 是另一独立轴。

**多条同时有效路线**放在 `route_selection` 切片，**不可完成回合**放在 `feasibility_decision` 切片；二者不冒充严格 L1。原 3 身体 × 3 难度的 9 格矩阵已被上述 12 格覆盖检查表替代；难度改为逐实例记录。

每格各选一个声明实例建立连续成功见证后再扩种子；不可完成配对另做证书和实体退出见证。未找到可行参数时保持 `unknown`，不将失败写成验证通过。

## 2. 共同场景与公开指令

场景包含高货架、容器、带可见标识的黄色目标块、低柜深处的交付托盘 D、可交互物品以及退出区 Q。目标不是货箱；同色物体由图案／编号与空间关系区分。Q 以边界和字母标示，布局随机且与出生区、D、正常作业区分开。对每个参与机器人均有无任务操作前提的地面通路；双机可用带分区的同一 Q，必须能容纳全部收拢后的整机包络。

> 将高处货箱中带有 {可见标识} 的黄色方块完整放入低柜内标记为 D 的托盘。托盘承托目标后再撤去机器人或所持物体的支撑，并使目标释放后稳定 2 秒。遵守公开的碰撞、载荷、关节和物体完整性限制。如果判断当前身体和现场物品无法完成任务，可以不先尝试抓取，让所有参与机器人空手移动到 Q 区并停稳 3 秒，结束本回合。

基础指令不暗示工具用途或参考解，不透露档位及可解标签。允许把指定机械臂的参与写成明确的任务约束，即使另一机器人物理上可以独自完成；这属于受约束的协作评测，不宣称机械臂在物理上不可替代。

### 路线规则：自由完成与指定机械臂交付

| 公开规则版本 | 可以直接用手取块吗？ | 怎样算完成？ |
| --- | --- | --- |
| `free_route` 自由路线 | 可以；也允许单机独立完成 | 任一合法路线满足目标交付与安全条件 |
| `required_manipulator_transfer` 指定机械臂交接交付 | 可以；直接手取可作为前段操作 | 必须将目标转交给回合开始前指定的机械臂，由它独立控制并完成低柜放置和释放 |

强制版本在基础指令中、退出条款之前加入以下公开要求：

> 本回合必须由 {交付机械臂标识} 接手目标，并由该机械臂完成低柜内的放置和释放。目标必须从另一参与机器人的控制或承托状态，直接交接或经独立支撑面中转，到该机械臂的独立控制状态；另一机器人随后不得继续支撑或接触目标。即使其他机器人可以直接取出目标并自行交付，也必须完成上述交接。取物时是否搬箱、是否使用辅助工具以及交接位置由你决定。

A 配置可指定 X5；B／C 使用对应配置中明确标识且有控制接口的交付机械臂。规则在回合开始前固定并公开，不能由评分器事后增加，也不因一次失败而切换版本。不可完成时的 Q 规则保留，但判断的是“在本回合公开约束下无法完成”；若自由路线可行而强制交接不可行，记录为 `task_constraint_infeasible`，不称为物理无解。

不能靠机械臂碰一下目标来满足要求。可信日志须确认供给者先控制／承托目标、接收机械臂随后独立控制、供给者退出目标接触，以及指定机械臂执行最终放置和释放。接收控制的保持阈值待标定冻结。经台面中转也可，但只搬外箱而没有目标承托链证据不自动算交接。直接手取后自行交付在自由版成功，在强制版记 `required_transfer_unmet`、任务不成功；实际物理交付仍单独记录，不伪称安全违规。

两个版本按规则分别统计，并绑定各自可行性见证和不可完成证书。强制参与不自动增加难度；若要声称“工具／机械臂在物理上必需”，仍需排除所有合法替代路线。

观测限于实际配置的相机／深度、编码器、IMU，以及确实装配的力、触觉或电流反馈。能力查询只能返回允许披露的机器人模型、校准和接口信息；不能返回目标真实位姿、隐藏物性、工具标签或当前实例可解性。工具几何由视角变化、深度和真实接触获得；额定能力可通过可见铭牌获取。隐藏摩擦／强度差异若无法安全观察，就不能要求 agent 准确放弃。

## 3. 族内场景配方与对照（保留原 ID）

下表是作者侧任务卡。工具名称仅用于设计说明，agent 看到中性物体名称。每条路线都是待验证假设；成功按目标物状态与本回合公开约束评判，不要求复现未公开的参考步骤。

| ID／任务 | 现场物品与候选完整路线 | 关键选择、证据与反例 |
| --- | --- | --- |
| **M1E-01 已知能力分工交付** | 合适的固定交接面已就位；搬下货箱→独立支撑→取块→进入低柜→托盘承托→撤手。若当前身体能直接取块，可跳过搬箱。 | Easy 基线。能力说明与实际配置一致；查全程负载、双机净空和撤手可达性。反例：仅搬箱、目标仍在柜口、持住目标未释放。 |
| **M1E-02 同身体能力变化后的重新交接** | 同一机器人、同一末端、同一布局，仅改变预声明的关节限制或控制能力；提供可调站位及固定交接面。探测可达性→选抓点／面→调整分工→交付。 | Medium，同身体能力适应。失败姿态不等于整机不能完成；编码器、碰撞观测与低风险探测支持换路线。限制在回合前锁定，公开安全限值始终可见。反例：复用原能力下的姿态、仅空载 IK 成功、重复撞同一箱沿。 |
| **M1E-03 选择支撑物后才能松箱** | 同时提供可搬支架、窄顶凳、承载不足的箱体；选可抓持且能承箱的支架→在交接区布置→搬箱并撤手→另一机器人取块交付。 | Hard 的首个瓶颈：持箱状态下两机不能安全取物，必须独立支撑。几何、铭牌及小载荷响应可观察。须排除直接取块、放地面、替代家具等绕开瓶颈的路线，或将其归为合理替代解。反例：仍暗中托箱、窄支架静态不倒但取块时倾覆。 |
| **M1E-04 支撑＋推车运输货箱** | 同时有承托支架、带可操作制动的推车、较短承载面的另一推车；在货架旁承接货箱→选合适车辆→真实装载→运输→停车制动→取块入柜。 | Hard，工具组合。检查机器人能装车也能停稳车，底盘＋车＋箱扫掠与负载抗倾覆。工具可用性不能仅由车能滚动推定；不允许用隐藏焊接代替车上支撑。反例：移动空车、目标仍在车上、车未固定就取块。 |
| **M1E-05 钩具、夹取器与直杆的选择** | 箱固定或当前身体不能搬箱；同时有可握持钩具、长夹取器、直杆和过短工具；用适配工具把块沿箱内底面移到可抓位置→抓取运输→入柜。 | Hard，工具长度之外还看握柄、腕矩、作用方向、箱沿和目标接触几何。给定目标上没有孔就不能假设可挂钩；可绕到块后侧的接触路线要实证。多条路线都有效才称多解。反例：工具够长但无法转入箱内；把目标拉出箱外自由落下。 |
| **M1E-06 低柜深处交付工具选择** | 取块可行，但当前末端不能深入托盘；有窄推杆、薄托板、厚托板，以及可选低位机器人。候选路线一：柜体连续承托目标、推至 D 后撤杆；路线二：托板送入、把承重转给柜体后撤板；路线三：换交付者。 | Hard，末段能力限制。验证柜内沿途支撑、工具撤出空间、目标真实边界与无工具残留支撑。目标必须由 D／柜体承托再释放；工具下的目标不能悬空下落到 D。反例：工具和目标一起留在托盘、柜口浅放、外部工具继续承重。 |
| **M1E-07 多种有效工具与完整路线比较** | 支架、推车、钩具、长夹取器和干扰件同时存在。比较“搬箱→支架→取块”与“工具移块→直接运块”等完整链；至少两条在同一身体同一场景有见证才标多有效路线。 | `route_selection`，Hard。选工具后必须检查低柜交付与工具撤出，不能只优化取物阶段。合规较慢的路线同样成功；动作数、时间与探测成本为次指标。反例：搬得下来却无法交接；长工具取到了但柜前无法换抓。 |
| **M1E-08 工具不适配后的恢复与换计划** | 两个外观相近、握柄／刚度／额定载荷不同的支撑或取物工具，加一个真实可行备选。先观察或安全试探→发现不适配→保持目标原支撑→退回稳定状态→换工具／交付者→完成。 | Medium／Hard 的重规划切片。差异在回合开始就确定且能感知；不强制 agent 先选错。记录关键证据后计划是否改变；直接选对也能得任务成功。反例：重复同一失败、把目标推坏后再声称初始无解。 |

工具充足不等于必须全部使用。若一件物体经组合后变得可用，就不能继续把它记为不可用干扰。03／04 的“必须用支撑／推车”只有在排除替代路线后才能作为研究标签；否则保留成功并修正标签。

## 4. 四类不可完成对照：观察后直接去 Q

不可完成性必须绑定初始场景、身体／末端、控制接口、公开规则与工具全集。当前只规定要构造的对照，**没有已认证不可解实例**。

| ID／配对任务 | 不可完成条件与必要证书 | 最小可完成配对变化 |
| --- | --- | --- |
| **M1E-I01 取物高度／深度超出全部合法路径**／05 | 箱固定；所有身体姿态和合法工具组合的保守接触范围都不足以取得目标；排除移箱、攀爬、从另一侧接近、倾倒接取等路线。可从几何与公开限位取得判断证据。 | 仅换成足够长且可操控的工具，或降低目标位置；建立完整交付见证。 |
| **M1E-I02 无法建立安全交接支撑**／03、04 | 当前身体不能持箱交接，也不能直接取块；所有可布置支撑／推车在可达性、承载或稳定性上至少失败一项，且地面放置、现有家具、工具组合、换交付者均不能绕过。 | 仅替换一个可观察承载能力／几何合格的支撑件。 |
| **M1E-I03 低柜入口存在不可绕开的几何瓶颈**／06 | 固定封闭柜体唯一入口在所有允许姿态下都无法让完整刚性目标通过；排除拆柜、变形目标与其他入口。不能只因某末端太宽就宣称无解。 | 仅增加入口的瓶颈尺寸，保留取物端与工具布局。 |
| **M1E-I04 工具与身体不匹配，所有转移链中断**／02、05、08 | 所有候选工具均无法由本配置建立有效抓持／作用力，且直接抓、推、托、双机协同、环境重抓和组合工具不能完成必要转移；按完整路线图检查每个分支。 | 同一身体只换末端，或只换一个工具握柄；其余保持不变。 |

每一对共用指令与 Q 布置分布，只有影响可行性的一个条件变化；该变化必须可观测。不能凭颜色、任务 ID、Q 位置或隐藏标签猜答案。I02／I04 覆盖所有替代路线较难，证据不全时保留 `unknown`，优先实现证书更清楚的 I01／I03。

“直接放弃”允许观察完即去 Q，不强制先抓取或失败。一次 IK 失败、控制器没找到解、超时或一个工具不适配均不能证明全场景无解；机器人自身破坏了原可行路线也不是正确放弃。

## 5. 实体退出和评分

退出流程为 `active → retreating → abstained`；其他终态为 `delivered / timed_out / invalid`。进入 Q 表达退出意图，但只在所有参与机器人同时满足退出合同后提交终态。进入／退出 Q 不重复发奖励；文字“give up”或 `declare_infeasible` 最多登记意图，不能代替实体移动。

**Q 退出合同（待标定草案）：** 所有参与机器人整机水平包络在 Q 各自允许区域内；站立或正常轮式支撑；无抓持、悬吊或通过手持工具间接控制的物体；机器人之间无碰撞；线速度 ≤0.03 m/s、角速度 ≤0.05 rad/s，连续 3 s；此前无硬违规。已动过的箱／目标／工具须留在允许位置独立稳定支撑。需先安全释放再进入 Q，不能带箱进区后丢下。Q 路线不可达的样本是生成错误，不能拿来测“无法完成操作后退场”。

| 初始可信标签 | 完成交付 | 全员有效退到 Q | 超时／部分机器人退到 Q |
| --- | --- | --- | --- |
| `witnessed_feasible` | `task_success=1` | `task_success=0, false_abstention=true` | 未完成／退出失败 |
| `certified_infeasible` | 保留有效交付，标记证书矛盾并复核、暂停该标签的统计 | `task_success=0, correct_abstention=true` | 未检出或退出失败 |
| `unknown` | 经完整验证可新增匹配见证 | `task_success=0, abstention_correctness=null` | 保留未确定标签及实际执行结果 |

`safe_exit` 与 `correct_abstention` 分别记录；安全退出不代表判断正确。只报告已认证可解回合的交付率、不可解回合的正确放弃率、可解回合误放弃率、退出执行成功率、违规率及未知数。平衡决策成功率为两类成功率的均值，缺一类则不出总分。始终退出在可解回合得 0；超时不算放弃。初始标签与执行结果独立保存，标签修订必须保留旧证书和运行。

跨身体评分提案另行版本化，原 `m1-scoring/2-supported-release` 不在本次修改：

| 原判据 | 扩展用途 |
| --- | --- |
| `container_handled` | 搬箱路线诊断，权重 0；直接取块不因此扣任务成功分 |
| `off_shelf` | 与机器人无关的目标物离架进度，拟议权重 0.2 |
| `mobile_grasp` | 替换为 `target_controlled`：通过真实抓持或合规、可维持的支撑控制目标；离开初始存放位置后才计，不能出生即得分；拟议权重 0.2 |
| `in_cabinet` | 目标真实边界相对 D 的位置进度，拟议权重 0.2 |
| `delivered` | 柜体先承托、机器人及所持工具后释放，目标完整入 D 并稳定保持到结束；拟议权重 0.4 |

主指标为满足该版本公开约束的有效终态；强制版本还须满足指定机械臂交接和最终交付条件，单独的物理 `delivered` 不足以构成任务成功。过程分只是诊断，不与正确放弃相加，不把未发生阶段补发满分。交付沿用原参考的 2 s 保持要求；无额外支撑、机器人／手持工具接触、速度与柜体承重阈值须校准并冻结。不能用单帧、投掷、残留工具承重或改写状态满足判定。

## 6. 分层规划、记录与对照

| 子任务 | 入口 → 出口 | 技能、支撑和失败处理 |
| --- | --- | --- |
| Observe / Model | 初始稳定状态 → 目标身份、身体能力和候选路线的观测证据 | 移动视角、读铭牌、查询允许的能力信息、低风险探测；缺证保留未知 |
| Prepare | 候选路线 → 可用且稳定的支撑／运输／取物工具 | 真实抓、推、放、制动；撤手验证独立支撑；不适配则保留原支撑并改计划 |
| Retrieve / Transfer | 目标由货架容器承托 → 离架且有持续控制／支撑 | 搬箱或移块、抓持、交接；不强制特定机器人；记录实际承重转移 |
| Transport / Insert | 稳定控制目标 → 目标进入 D 并由柜体承托 | 持物移动或受支撑推移；检查机器人、目标及工具的联合扫掠和撤出路径 |
| Release / Verify | 柜体承托 → 全部机器人及手持工具撤出，稳定 2 s | 接触时序、载荷、真实包络；失败则在仍受支撑的状态调整 |
| Exit | 初始观察或稳定操作状态 → 全员空手 Q 内停稳 3 s | 安全安置已动物体、收臂、行走／行驶、停稳；无法退场不伪造退出成功 |

段间传递实际位姿、速度、抓持、接触拓扑／力、支撑几何、阶段提交、剩余预算和估计不确定性。各子任务可从可信参考检查点或合法生成后静置的状态独立诊断；检查点起跑不算连续全程成功，也不向正式评测 agent 开放。

保留两种身体对照：`matched_world` 固定货架、目标、工具布局换身体；`same_body_capability_change` 固定外形／任务布局，改变定义明确的末端、关节限位或控制能力。不要把按身体重新缩放场景混入同场景对照。

另测：①能力完整披露 vs. 需要探测；②换身体后沿用原计划 vs. 重新探测并规划。记录能力查询、探测动作、工具选用、首次不可达／抓取失败、证据出现后的计划变化、耗时、token、无效交接和退出延迟。不能靠一段自述给 self-modeling 分；这些对照的成功率和成本差距是行为证据，不是单独的因果证明。

## 7. 实施与验收边界

遵循 infra 的 R1–R11：Genesis 后端、优先官方机器人和精细物体资产；版本、资产来源／许可证／哈希、尺度／碰撞／惯量、控制器、传感器规格、力矩与载荷硬限、仿真步长和接触设置均逐配置冻结，现为待定。Isaac Lab 对齐单列，不能借用另一个后端的结果。弱支撑与失稳要有真实物理机制及可观察线索，不能只增加隐藏扣分规则。

随机化对象包括货架高度、箱沿／目标位置、交接位置、柜口与 D 深度、工具尺寸／握柄／额定载荷、质量／摩擦和 Q 位姿。数值范围、开发／密封评测划分、各类样本数与探测预算目前为 null；没有启动求解器。无效几何、出生重叠和 Q 不可达记录拒绝原因与比例；正式样本的未知、失败和超时全部保留，不换 seed。

四态账本沿用 `witnessed_full / screen_pass / unknown / rejected`；`certified_infeasible` 是需证书的初始决策标签，只有覆盖全实例的必要条件反例才可关联，不从单路线 `rejected` 自动推导。每格／声明工具层预声明有限代表样本、三层动作映射与至少一个连续生成的成功见证；局部技能检查和短探测不能冒充全程成功。不要求逐随机实例完整求解。代表运行重复 3 次、回合评分重复 3 次，其他容差和数量冻结后执行。

实施优先级见独立 case 表；原操作编号仅为父分组，02／07／08 已各有独立子 case，04 和 I02／I04 仍暂缓。

评分反例覆盖七类：私读真值／证书、改世界或瞬移到 Q、穿模／隐藏固定／注能、错目标／投掷／单帧／跌入 Q、重复退出／叠加阶段奖励、记 seed／颜色／Q 布局、绕过预设路线。合理替代路线通过物理终态给分并修订标签，违规反例不得成功。还需测一台进入 Q 而另一台仍持箱、目标留在工具上、始终放弃、超时伪装退出、先破坏路线再放弃。以上为计划，尚未运行评分测试。

人工审阅逐项检查目标身份和完整入 D、支撑先于释放、双机与工具接触、公开限值、Q 全员轨迹和驻留、不可解证书的替代路线覆盖、可完成配对见证、源码／资产／日志身份。审阅人与第二人复现均待指定；不自动提升准入状态。
