1. 目标与首批交付

将 0.4 kg 包裹穿过自闭门，放在 B 桌并稳定释放。

面对相同目标和物理机制，agent 能否通过发现工具、理解自身与队友能力边界，自主选择并执行有效的协作方案？

G1 搬运原包裹，Stretch 扶门或布置工具。L1 已有完整原生见证；L2/L3 按用户要求作为后续扩展独立推进，不阻挡 L1 单独验收。

P0/P1/P2 是实施优先级，L1/L2/L3 是评测难度。工作项 ID 与配置 ID 分开；具体实测、冻结版本及正式验收缺口见实施看板。

2. 必须满足的要求

R01 · 机制与难度分开

heavy_prop 与 no_prop 是并列机制变体。L1/L2/L3 按物理约束、信息不确定性与决策需求定义。

R02 · 保持配对公平

修改包裹、把手或场景时，为所有对照机器人使用同一新版本；单纯换型号不证明 self-modeling。

R03 · 全过程物理验证

同步记录门角度、角速度、支撑接触、包裹和机器人状态；检查组合包络从进入门区到完全离开的净空与支撑。最终接触力不能替代连续证据。

R04 · 能力预测可检验

动作前记录可达、推力或抓取预测，动作后对照实测；证据不足记未确定。比较固定分工、主动探测和关闭更新的对照。

R05 · 隐藏信息有边界

公开名义规格和合法控制接口；隐藏实际能力扰动、工具物理参数及故障真值。特权参考只用于可行性，不计为公开观测 agent 表现。

R06 · 预算先验证后冻结

新组合先证明可行，再冻结预算；不直接沿用 180 秒。探测、通信、执行与恢复成本分别记录并纳入预算。

R07 · 证据分层管理

保留完整成功见证／通过可行性筛查／未确定／检查不通过。资产加载、局部验证、任务成功和正式准入分别记录，不要求每个随机 seed 都有完整专家解。

R08 · 保留全部失败

冻结参考成功数不是随机场景成功率。跨版本结果不得混算，新配置未验证时不得标为完成。

R09 · 明确协作形式

首轮采用集中式 agent 控制双机。若研究独立多 agent，另行冻结各自观测、通信权限、延迟和同步规则。

R10 · 真实执行与合法故障

运行中禁止通过位置重设、隐藏吸附或修改物理参数制造成功；L3 仅允许可信侧执行预声明故障，保留原始记录。

3. 三个难度层级

层级 核心问题 验收重点
L1 · Known Coordination 已知门机构与能力的协作执行 持续扶门或重箱支撑，完成交付；对应已有双 G1 冻结参考。
L2 · Tool & Role Discovery 发现工具并选择分工 实测工具有效性、验证支撑并解决单臂资源竞争。
L3 · Capability-Aware Adaptive Cooperation 隐藏能力与在线故障 动作前预测、能力更新、角色切换与恢复。

6. 诊断指标与事件轨迹

指标 定义与记录要求
Tool Discovery Success 撤去辅助后，选定工具是否维持有效支撑并允许实际通过；持续扶门另记策略。
Capability Prediction Accuracy 动作前预测与实测结果的一致性，记录置信度与未确定项；不能用事后解释替代预测。
Role Allocation Quality 分工可行性、失败重分配次数及相对同条件参考的成本；未定义成本时不声称最优。
Support Continuity 整个穿门区间的最小净空、支撑中断时长、支撑来源和交接事件；阈值通过物理验证后冻结。
Recovery Success 在预声明且可恢复的故障实例中，恢复安全支撑并完成交付；记录不可恢复实例。
Probe / Execution Cost 探测动作、仿真时间、观测／通信次数及每台机器人占用时间，恢复额外成本单列。

沿用现有 200 Hz 物理记录作为起点。原始状态、控制指令、支撑来源、穿门区间、故障事件和评分版本必须能够同步对齐与独立复核。局部门槛在各冻结试验计划和审计中记录；新配置完整评测预算仍待冻结。
