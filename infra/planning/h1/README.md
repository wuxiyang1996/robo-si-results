## 如何运行筛查

在仓库根目录运行，输出必须使用新文件名：

```powershell
python -B infra/planning/h1_screening.py --input infra/planning/h1/draws.json --witnesses infra/planning/h1/registry.json --out <新的账本.json> --wall-seconds 60 --max-candidates 3
```

输入 `draws` 保留完整抽样顺序，包含场景、seed、split、控制器／源码／物理身份、高层计划、技能选择与关键状态要求。新样本不应伪造或借用旧样本的身份哈希。

当前已实现：场景身份绑定、完整见证逐文件哈希核验、必要的物体尺寸检查、预算限制、逐样本保留和四态汇总。完整见证缺文件、哈希不符、身份不一致或预算不足，均不能获得完整成功状态。预算到达后停止检查，剩余抽样仍逐条记 `unknown`。

可达性／扫掠碰撞、接触承重、跨技能入口与执行时间可行性尚无通用自动求解器；未取得相应证据时保持 `unknown`。仅尺寸合法不会得到 `screen_pass`。分类接口支持未来接入有证据的检查器；全部必需检查通过才能得到 `screen_pass`，仍不等于完整执行成功。

短仿真预算在当前入口固定为零，程序没有仿真、容器或求解器启动调用。运行时局部规划是设计要求，现有分阶段控制器不被包装成已经实现的通用滚动规划器。

- 未知技能范围和实例允许显式保持未知；不能声明整个随机范围已证实可解。
- 人工签审、第二人复现和其他未完成的正式准入 gate 继续保持未通过。仿真保持暂停。
